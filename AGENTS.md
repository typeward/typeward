# Typeward — agent notes (Codex / generic)

> Mirror of `CLAUDE.md`. Keep both in sync when one is updated. The content is tool-agnostic; pick the file that your agent loads. Body last fully synced 2026-06-11; the 2026-08-04 open-source pass and the 2026-08-05 Dropbox-removal / texlive-wasm-npm pass (both below) are applied here as well. Where the two files disagree on anything else, `CLAUDE.md` is canonical.

Multiplatform editor app similar to Overleaf, format-agnostic: LaTeX and Typst, with live `.md` file preview. Targets desktop (Win/Mac/Linux) and tablets (iPadOS, Android tablets — no phones). Local-first; cloud sync of *project files* is optional and runs through a WebDAV host the user configures. (Jupyter `.ipynb`, Quarto, R Markdown, and Markdown-as-project are out of scope.)

**Licensing and business model (2026-08-03).** Typeward is open source under **GPL-3.0-or-later** — the root `LICENSE` is the verbatim GPLv3 text, `package.json` and `src-tauri/Cargo.toml` both declare `GPL-3.0-or-later`, and `THIRD-PARTY-NOTICES.md` + `LICENSES/Apache-2.0.txt` cover the vendored Apache-2.0 `harper-core`. **There is no paid tier, no entitlement gate, no account, and no backend.** Every feature is unconditionally available: Typst, all reference integrations, git/GitHub, Overleaf import, all AI providers, Harper grammar, cloud sync, custom templates, and every template in the gallery. Don't add a gate, a tier check, a sign-in surface, or a "Pro" affordance.

## Architecture seams — read before adding format-specific code

- **Integrations module** (`src/integrations/`, `src-tauri/src/integrations/`) — the substrate every third-party integration plugs into. Provider interfaces (`CitationProvider`, `CloudFsProvider`, `AiProvider`, `GrammarProvider`, `TemplateProvider`) live in `src/integrations/types.ts`. Each category has its own registry + init module that watches `integrationsSettings()` and registers providers reactively (`references/init.ts`, `cloud/init.ts`, `ai/init.ts`). `App.tsx` wires the inits at boot alongside `bootCoreCommands()`. Shared Rust primitives: `integrations::credentials` (OS keyring, service prefix `typeward.<provider>`, `credential_exists` for UI checks), `integrations::http` (`http_request` / `http_request_bytes` — allowlisted outbound funnel; `authRef` secrets are resolved from keyring inside Rust and bound to expected hosts), `integrations::oauth` (PKCE + `axum` loopback callback on `127.0.0.1:0`).
- **`EditorAdapter`** (`src/adapters/<format>/`) — per-format glue: CM extensions, compile delegate, preview kind, diagnostics, completions, commands. Two concrete impls today: `LatexAdapter` (`compile_latex` → latexmk/pdflatex or Tectonic), `TypstAdapter` (`compile_typst` → native typst CLI). Each calls IPC directly; the `CompileProvider` interface in `src/providers/types.ts` is still aspirational. The format → adapter mapping lives in two places that must stay in lockstep: `src/commands/actions.ts` `adapterFor()` and `src/screens/editor/EditorScreen.tsx` `adapterForFormat()`.
- **Markdown files** — when the active editor tab is a `.md` file, the right pane swaps from `<PdfViewer>` to `<MarkdownPreview>` (markdown-it + local KaTeX renderer + DOMPurify; lives at `src/components/preview/MarkdownPreview.tsx`). Sandboxed HTML render with guarded relative-asset rewrite against the active file's directory; direct `file:` URLs, parent traversal, absolute paths, and unknown schemes are rejected. Debounced ~80ms. Does not participate in compile. See `docs/ntb_feature.md` for the removal rationale (its companion design spec was deleted with the superpowers tree — recover from git history if ever needed).
- **`CommandRegistry`** (`src/commands/`) — wired through end-to-end. `bootCoreCommands()` runs at app startup; adapter commands register on project load (`EditorScreen`) and unregister on cleanup. The shared `<CommandPalette />` rendered at App root reads from `commands()` directly. Global shortcuts (`Mod+K`, `Mod+N`, `Mod+,`, `Mod+S`, format-specific compile) dispatch through `src/commands/keyboard.ts` — CodeMirror no longer hardcodes `Mod-s` / `Mod-Enter`. Save/compile orchestration lives in `src/commands/actions.ts` (single point that maps `project.format` → adapter). Editor-scoped commands gate on focus being inside `.cm-content` or `[data-editor-shell]`.
- **LSP transport** (`src/lib/lsp/client.ts` raw + `wrap()` JSON-RPC wrapper, `src/lib/lsp/cm6.ts` CM6 integration, `src/stores/lsp-store.ts`) — Rust owns child processes (`src-tauri/src/lsp.rs`); frontend talks over Tauri **event channels** (`emit`/`listen`), not `invoke` for streaming traffic. `invoke` is only used for `start_lsp` / `stop_lsp` / `send_lsp_message` lifecycle and outbound writes. **We hand-rolled the CM6 binding** rather than using `codemirror-languageserver` (that package is coupled to `@open-rpc/client-js` WebSocket transport).
- **Unified file watcher** (`src-tauri/src/watcher.rs`, `src/lib/watcher/client.ts`, `src/stores/watcher-store.ts`) — single `notify` service, frontend `fsVersion` signal bumps on each event, FileTree reads it as a resource key. `.typeward/` paths are filtered to avoid autosave feedback loops.
- **Autosave** (`src/lib/autosave/index.ts`, `src-tauri/src/autosave.rs`) — debounced 500ms; snapshots to `<project>/.typeward/snapshots/<rel>.snap`; `RecoveryDialog` shows orphans on project open.
- **Telemetry** (`src/lib/telemetry/index.ts`, `src-tauri/src/telemetry.rs`) — Rust panic hook + frontend `error`/`unhandledrejection` → JSONL log at `<app_data>/telemetry.log`. Capture only; no submission UI.
- **Responsive layout** (`src/stores/viewport-store.ts`, `src/components/layout/PaneSwitcher.tsx`, `src/lib/gestures.ts`) — `viewportMode()` flips at the 1024px breakpoint. `TextShell` keeps a desktop `DesktopLayout` (corvu Resizable, unchanged) and a tablet variant that swaps in `<Switch>`-based single-pane rendering, the `PaneSwitcher` segmented control, the slide-up `LogsSheet`, and a swipe listener. `setActivePane()` is the public lever for pane navigation; treat `cyclePane()` as gesture-only. Don't add fixed-width assumptions in shells — guard behind `isTabletViewport()` instead.
- **texlive-wasm CompileProvider** (`src/providers/compile/texlive-wasm-provider.ts` + `texlive-wasm-assets.ts`) — mobile-only Web Worker LaTeX engine via **`@typeward/texlive-wasm`, an ordinary npm dependency pinned at `0.2.4-alpha`** (Typeward's MIT-licensed sibling project, published rather than linked since 2026-08-05 — a plain `npm install` from a bare clone is all it takes). Only the **module specifier** is scoped: the engine *identifier* `"texlive-wasm"` — the `CompileEngine` union member, the asset directory names, the `$RESOURCE/texlive-wasm/**` capability globs — is deliberately unscoped and must stay that way. Selected when `compileEngine() === "texlive-wasm"`; not available on desktop. `LatexAdapter.compile()` dynamic-imports the provider so the WASM bridge isn't pulled into desktop bundles when unused. **Assets live in two places on purpose** (`texlive-wasm-assets.ts` is the single source for both): the **engines** (glue `.js` + `.wasm`) go under `public/texlive-wasm/<engine>/emscripten/` because the worker `import()`s the glue and `fetch()`es the wasm *by URL*, and only the app's own origin satisfies the CSP; the **TeX Live tree** goes under `src-tauri/resources/texlive-wasm/texmf/` and is read lazily off disk as a Tauri resource. It is bundled on **mobile only** — `bundle.resources` in `tauri.conf.json` lists just `resources/templates/**/*`, and the `tauri.android.conf.json` / `tauri.ios.conf.json` overlays add the texlive glob back. Tauri merges overlays with RFC 7386 JSON Merge Patch, where **arrays replace rather than append**, so each overlay must restate the full list — dropping `templates` from it would silently un-bundle the built-in templates. Every engine needs an explicit `enginePath` or the worker throws `config.enginePath is required` at init; the availability probe checks glue + wasm + a non-empty TDS and returns an actionable unavailable-state rather than failing inside the worker. Compilation goes through `latexmk()`. PDF bytes are persisted via the project-scoped `write_project_binary_file` IPC into `<project>/.typeward/build/<base>.pdf` so the existing file-path-driven PdfViewer renders it unchanged. Diagnostics route through the shared Rust parser via the `parse_latex_log_cmd` IPC. The provider walks both text dependencies (`.tex`, `.bib`, `.cls`, `.sty`, etc., read via `read_project_text_file`) and binary figures (`.png`, `.jpg`, `.jpeg`, `.pdf`, `.gif`, `.eps`, via `read_project_binary_file`); capped at 200 files / 10 MB combined.
- **Reference aggregator** (`src/integrations/references/aggregator.ts`) — `refreshLibraryBib(project)` calls `exportAllAsBibTex()` on every registered `CitationProvider` (Zotero Better BibTeX, Zotero Web, Mendeley), pulls in `<project>/.typeward/citations/local.bib` (DOI/arXiv lookups land here), dedupes by citation key, and writes the unified result to `<project>/.typeward/citations/library.bib`. The texlive-wasm walker auto-discovers it; texlab/tinymist see it as a normal `.bib` and provide `\cite{}` completions for free. Per-provider config lives in `IntegrationsSettings.references.{betterBibTex,zoteroWeb,mendeley}`; tokens live in the keyring under service names matching the provider id. (JabRef `.bib`-file import was removed 2026-06-13.)
- **Local user profile** (`src-tauri/src/profile.rs`, `src/screens/settings/ProfileSection.tsx`) — the persisted settings section `profile` (`displayName`, `email`, `affiliation`, backend-owned `avatarPath`) is the app's only notion of "who you are". It is local-only: no account, no sign-in, no network. `set_profile_avatar` validates the extension (png/jpg/jpeg/webp/gif), rejects symlinks and non-regular files, caps the file at 8 MiB, and copies it into `<app_data>/profile/avatar.<ext>`, keeping exactly one; `clear_profile_avatar` removes it. `tauri.conf.json`'s `assetProtocol.scope` includes `$APPDATA/profile/**` so `convertFileSrc` can render it. `settings.rs`'s `merge_backend_owned` carries `avatarPath` forward so a renderer settings roundtrip can't drop it. The profile name+email are the **fallback** git commit author (explicit `integrations.vcs.git.authorName`/`authorEmail` still win) and seed a template's `author` variable default. Settings mounts it in the `profile` section — the slot the old Account section used.
- **Cloud sync engine** (`src/integrations/cloud/core/engine.ts`) — generic bidirectional orchestration. **WebDAV (`cloud/webdav/`) is the only cloud backend** — Nextcloud, ownCloud, any WebDAV host; `CloudProviderId` is the single-member union `"webdav"`. Dropbox was removed 2026-08-05 (provider, OAuth flow, `VITE_DROPBOX_CLIENT_ID`, the `*.dropboxapi.com` outbound-allowlist and `www.dropbox.com` OAuth/opener entries) — WebDAV needs no registered app and no client id, which is the point. The engine, conflict resolution and the `.remote-cache` layer stayed generic and untouched; adding a second provider means implementing `CloudFsProvider` and widening that union, not reworking the engine. A project whose `.typeward/project.json` still carries `cloudOrigin.provider === "dropbox"` reads as **not cloud-backed** (`readCloudOrigin` in `cloud/registry.ts` returns null): it opens, edits and compiles as a plain local folder, nothing on disk is rewritten, and no sync chip renders. Don't add a migration that mutates those files. One `SyncEngine` per active cloud-backed project. Local cache layout: `<projectsRoot>/.remote-cache/<provider>/<projectId>/`; the cache *is* a normal Typeward project (same `.typeward/` sidecar, same watcher, same compile pipeline). Provider state under `<cache>/.typeward/integrations/<provider>/` (cursor + ID/path map + `sync-state.json`). **Pull** drains every delta page in one pass; **push** is queued from the save path — `saveActiveFile`/`saveAllDirtyFiles` call `notifyLocalSave(rootPath, relPaths)` (`cloud/init.ts`), which feeds `engine.queuePush()`; uploads coalesce on a 1.5s debounce and retry on a 15s backoff. Pull and push are serialized through one promise chain (`runExclusive`) so they never interleave on the shared cursor/cache. **Echo suppression:** each upload records its returned `rev` keyed by relPath; when the next delta replays our own write, the matching rev makes the engine skip it instead of minting a spurious `.conflict-*` sidecar. The persisted sync state records provider id/rev plus local content hash/size/mtime for each synced file; conflict detection compares remote rev changes against local hash changes instead of relying on filesystem mtime alone, and remote-delete vs local-edit preserves the local file as a `.conflict-*` sibling before removing the canonical path. The snapshot autosave does NOT push (`.typeward/` is rejected in `normalizeRemoteRelPath`). Remote relative paths are normalized before cache IO; absolute paths, parent traversal, Windows drive prefixes, NULs, and `.typeward/` targets (case-insensitive, any depth) are rejected. Conflict resolution writes the loser to `<name>.conflict-<ISO>.<ext>`; `<ConflictResolverDialog>` (reachable by clicking `<SyncStatusBadge>` when conflicts > 0) resolves them. Engine lifecycle in `cloud/init.ts` — when a project with `integrations.cloudOrigin` becomes active, the matching provider instantiates from settings and the engine starts. Provider factory `cloudProviderForAccount(ref, { projectsRoot, projectId })` in `cloud/registry.ts`.
- **AI streaming primitive** (`src-tauri/src/integrations/ai/streaming.rs`, `src/integrations/ai/stream.ts`) — one Rust task per stream, format-specific parsers in `parse_event()` (AnthropicSse / OpenAiSse / GeminiSse / OllamaNdjson). Chunks emit on a per-stream Tauri event channel `ai-stream:<streamId>`; stream ids are restricted to short ASCII `A-Z a-z 0-9 _ -` values and duplicate ids are rejected so abort handles cannot be orphaned. The frontend `aiStream(req, signal)` AsyncIterable adapter listens, yields each delta, calls `ai_stream_abort` when the AbortSignal fires. Stream URLs pass the same outbound allowlist as `http_request`; OpenAI/Anthropic/Gemini keys use `authRef` and stay in Rust. Error bodies and unterminated stream buffers are capped to avoid unbounded memory growth from attacker-controlled endpoints. All four providers (Claude/ChatGPT/Gemini/Ollama) implement the same `AiProvider` shape (`models()` + `chat(messages, opts)`); only one is active at a time per `IntegrationsSettings.ai.activeProvider`. `integrations.ai.enabled` **defaults to `false`** on both the TS and Rust sides — the AI surface used to be masked by the entitlement, so an on-by-default switch would hand every user an AI pane with no provider configured. Grammar defaults false for the same reason.
- **Local git** (`src-tauri/src/integrations/vcs/git.rs`) — libgit2 via the `git2` crate, every operation wrapped in `tokio::task::spawn_blocking` because libgit2 is fully synchronous. HTTPS auth comes from the keyring under service `git.<host>` so a single GitHub device-flow sign-in covers both REST API calls (via `httpRequest` `authRef`) and libgit2's push/pull callbacks. SSH transport is out of scope; only HTTPS + PAT, and git IPC now rejects non-HTTPS remotes (`file://`, SSH URLs, scp-style remotes). `git_pull` is fast-forward only and refuses to checkout when the worktree has staged, unstaged, or untracked changes — merge commits still need a conflict UX we don't ship yet.
- **Harper grammar** (`src-tauri/src/integrations/grammar/mod.rs`, `src/lib/grammar/cm6.ts`) — Rust-native, runs in-process via `harper-core`. `grammar_check(text, file, syntax)` IPC returns diagnostics in the same shape as compile/LSP diagnostics so the existing gutter renders them without changes. CM6 linter extension via `@codemirror/lint`, debounced 400ms; up to 3 quick-fix actions per lint. Wired into the editor only when `integrations.grammar.enabled` — zero IPC when off.
- **Templates** (`src-tauri/src/integrations/templates.rs`) — `templates_list()` merges built-ins from `<resource>/templates/` (bundled per `tauri.conf.json` `bundle.resources`) with user customs at `<app_data>/templates/custom/`. Each template ships a `template.json` manifest plus its files; `template.files[*].template = true` opts a file into Handlebars-subset `{{var}}` substitution at `template_instantiate` time. Other files copy verbatim. IDs are namespaced (`builtin:<id>` / `custom:<id>`) so short names don't collide across sources. `template_save(project, name, description)` does the reverse — captures the open project into `<app_data>/templates/custom/<id>/` (skips `.typeward/`/`.git/`/symlinks/LaTeX build junk, copies the rest verbatim, writes a `template.json` with empty `variables`/`files`). Triggered by the `core.saveTemplate` command → `<SaveTemplateDialog>` mounted at the App root via the `requestSaveTemplate` signal.

- **No backend, no accounts** (removed 2026-08-03) — the Supabase auth + entitlement chain is gone: `src/integrations/supabase/` (client, session, storage, entitlements-source, settings-sync, database.types), `src/config/supabase.ts`, `src/integrations/entitlements.ts`, `src/components/entitlement/` (FeatureGate, ProChip, ProLockedPanel, ProDialog, pro-gate), `src/config/pro.ts`, `src/integrations/auth/chunked.ts`, `src/components/account/`, and `src/screens/settings/AccountSection.tsx` were all deleted, along with the `Tier` / `EntitlementKey` / `KNOWN_ENTITLEMENT_KEYS` / `EntitlementSource` types in `src/integrations/types.ts` and `TemplateManifest.entitlement`. On the Rust side: `build.rs` is back to `fn main() { tauri_build::build() }` (the Supabase CSP splice and its `serde_json` build-dep are gone, so `tauri.conf.json`'s `csp`/`devCsp` are standalone and complete), `credentials.rs` lost `supabase_session_read` / `credential_get` / `frontend_read_allowed` / the chunked-session reader, `settings.rs` lost `SyncSettings` / `AccountSettings` / `sync_state_path` / `load_sync_state` / `save_sync_state`, and `ipc_guard.rs` no longer lists `supabase_session_read`. Don't reintroduce any of it.

## Gotchas

- **Sync Tauri commands run outside the tokio runtime.** Calling `tokio::spawn` from a sync `#[tauri::command]` panics with "no reactor running" and aborts the process (Windows reports `STATUS_STACK_BUFFER_OVERRUN` / `0xc0000409`). Mark any command that touches tokio (`spawn`, `mpsc`, `tokio::process`, etc.) as `pub async fn`. Reference: `watcher.rs::watch_project`.
- **Tauri 2 fs plugin scope = static capability entries UNION the runtime scope.** `fs:default` + bare `fs:allow-*` permissions don't grant access to arbitrary paths, and the plugin checks `capability_scope.is_allowed(path) || runtime_scope.is_allowed(path)` (a runtime *forbid* still wins over both). Since 2026-07-13 the static entries in `capabilities/default.json` cover only the DEFAULT projects root (`$DOCUMENT/Typeward/**`) plus `$RESOURCE/texlive-wasm/**` — **not `$DOCUMENT/**`** — and `lib.rs::grant_projects_root_fs_scope` adds the *configured* projects root to the runtime scope at startup and again from `save_settings`. Dialog-picked paths are added to that same runtime scope by `tauri-plugin-dialog`. Custom project IPC (`read_project_text_file` / `write_project_text_file` / `write_project_binary_file`) still validates canonical project-relative paths. **`fs:allow-read-file` (binary) is separate from `fs:allow-read-text-file`** — PDF reads need the binary one. Don't reintroduce a Documents-wide static grant; widen the runtime scope instead, and only for a path the user chose.
- **PDF.js `RenderingCancelledException`** is benign — fired whenever a render is superseded by a newer one (e.g., on quick recompile). `PdfViewer` uses a generation counter and silently swallows it. Don't surface it as an error.
- **Custom Tauri commands bypass fs plugin scope** — project file IO must use `read_project_text_file` / `write_project_text_file` / `write_project_binary_file`, which validate project-relative paths against the canonical root. Compile commands also validate `project.rootFile`. Don't reintroduce raw absolute-path file IPC.
- **CodeMirror remount on tab switch** — `text-shell.tsx` keys CodeMirror on `activeFile().path` so the LSP gets a fresh `didOpen` per file. Don't try to swap content in place via dispatch; that breaks LSP doc tracking.
- **`@fontsource-variable/inter` + `@fontsource-variable/jetbrains-mono`** ship variable fonts (one axis file per family, plus an italic axis file). They block initial paint in dev — biggest contributor to the pre-paint flash before `backgroundColor` in `tauri.conf.json` made the window paint in the default theme's bg on creation (`#F8F4EA` since the Daylight default). The boot splash in `index.html` defaults to Daylight colors and `public/boot-theme.js` re-tints it from the persisted theme, so dark-theme users don't get a cream flash. A previous `visible: false` + `getCurrentWindow().show()` deferred-reveal pattern was removed: it masked render-time crashes (window stayed hidden if `onMount` never fired), and the static background alone is sufficient.
- **Compile fallback chain**: `system-tex` engine tries `latexmk` first, falls back to `pdflatex` on spawn/exit failure (MiKTeX sometimes ships latexmk without a usable Perl). `tectonic` engine tries the sidecar (`binaries/tectonic-<triple>`) first, falls back to `tectonic` on PATH. Either way, the actual command + log get surfaced in the LogsDrawer's Logs tab.
- **Typst syntax highlighter is hand-rolled.** `src/adapters/typst/typst-language.ts` is a minimal CM6 `StreamLanguage` covering the visual basics (comments, strings, math, `#funcs`, headings, emphasis). It's intentionally not a full grammar — when tinymist's structured tokens become consumable through the LSP transport, prefer those over expanding this parser.
- **SyncTeX shells out to the system `synctex` CLI** (`src-tauri/src/synctex.rs`), not a Rust binding. TeX Live / MiKTeX / MacTeX all ship it; the CLI returns `Ok(None)` if not on PATH so Tectonic-only users get a graceful "no sync" rather than an error. Compile flags: `-synctex=1` for latexmk/pdflatex, `--synctex` for tectonic. Forward search wires through `requestPdfScroll(page, y)` → PdfViewer's `scrollTarget` effect. Inverse search uses **shift+click** on PDF page → `onPageClick(page, x, y)` (coords divided by current zoom to get PDF pts) → `requestGotoSource(relPath, line)` → EditorScreen opens the file and moves the cursor via the imperative `editor-view-store` handle.
- **Linux dev hosts need `libdbus-1-dev`** for the `keyring` crate's Secret Service backend, plus `libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev` for Tauri's GTK chain. Apt one-liner: `sudo apt install -y libdbus-1-dev libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.
- **Tectonic sidecar naming** — `fetch-tectonic.mjs` downloads the musl static binary (`tectonic-x86_64-unknown-linux-musl`), but Tauri's build script looks up the rustc target triple (`tectonic-x86_64-unknown-linux-gnu` on Linux). Symlink `gnu → musl` after fetch if Tauri build complains: `ln -sf tectonic-x86_64-unknown-linux-musl tectonic-x86_64-unknown-linux-gnu` in `src-tauri/binaries/`. The musl binary works fine on glibc systems — it's statically linked.
- **OAuth client ids come from `.env`** as `VITE_<provider>_CLIENT_ID`; Mendeley and GitHub each need their own registered app. The code paths are valid without the env vars — sign-in just throws an actionable "register your app at <url>" error. **Two different flows, and only one of them is `runOauthFlow`.** GitHub uses its own **device flow** (`src/integrations/vcs/github/auth.ts`: poll `github.com/login/device/code`, no redirect, no loopback server, no `oauth_begin`). **Mendeley is the only `runOauthFlow` / `oauth_begin` caller left** — since the Dropbox provider was removed (2026-08-05) no PKCE *public* client is wired up at all, though the PKCE machinery in `integrations::oauth` is intact and is what a future public client would use. Mendeley is a *confidential* client: it doesn't support PKCE and exact-matches the redirect URI with no dynamic ports, so its flow passes a `client_secret` (keyring service `mendeley`, account `app-secret`, entered in Settings — never an env var) plus a full `redirect_uri` the user pastes from their Mendeley registration (default `http://localhost:5000/callback`, persisted in `references.mendeley.redirectUri`). That override is loopback-validated in Rust (`parse_loopback_redirect`: http + `localhost`/`127.0.0.1`/`::1` + explicit port); a caller that omits it still gets the random `127.0.0.1` port.
- **`http_request` returns text body; binary needs `http_request_bytes`** — the text variant truncates non-UTF-8 payloads, so anything moving raw bytes over the allowlisted funnel must use the binary IPC and its `httpRequestBytes` wrapper (`src/integrations/http.ts`). Both commands enforce an outbound host/scheme allowlist; `authRef` credentials are bound to expected provider hosts and raw auth headers are rejected for metadata-only hosts. **As of 2026-08-05 `httpRequestBytes` has zero callers in `src/`** — Dropbox was its only consumer and WebDAV moves bytes over its own `webdav_get` / `webdav_put` SSRF-screened client. Both halves were kept deliberately: it is a live, tested primitive with no current consumer, and it is the right thing to reach for the next time a provider needs binary IO. If it is ever removed, remove the Rust command and the TS wrapper **in the same change** — `src/ipc/drift.test.ts` fails on a command registered on one side of the bridge only.
- **The frontend cannot read secrets from the keyring at all.** The generic `credential_get` IPC was deleted with the account layer (2026-08-03) — `credentials.rs` now exposes only `credential_set` / `credential_exists` / `credential_delete` to the renderer, plus the internal `get_secret` used by Rust for `authRef` resolution. Use `credential_exists` for UI state and `authRef` for API-key/bearer attachment; don't add a read-back path.
- **`git_pull` is fast-forward only and requires a clean worktree.** Merge commits surface as an error verbatim — the user resolves by hand for now. The conflict surface that would handle non-fast-forward pulls is the same gap that keeps SSH transport out of scope.
- **OS keyring on Linux blocks on D-Bus.** All `credential_*` IPC handlers spawn-blocking around the sync keyring API so the Tokio runtime (LSP / watcher / autosave / cloud sync) doesn't park during a Secret Service unlock prompt. New keyring callers should follow the same `tokio::task::spawn_blocking` pattern.

- **In-app feedback submission is gone; the GitHub-issue path stays.** `feedback-submit.ts`, `feedback-prompt.ts`, `FeedbackCard.tsx`, and the `requestFeedbackCard` signal were deleted 2026-08-03 because the form POSTed to a Supabase edge function. ## Security invariants (established 2026-06-10 audit)

Threat model: local user is trusted; adversaries are malicious project content (cloned repos, Overleaf zips, custom templates, `.md`/`.tex`/`.bib`/log files) and attacker-controlled remote content (cloud-synced files, Zotero/Mendeley records, git remotes, AI endpoints). Webview XSS = arbitrary IPC = file write + process spawn, so the `.md` preview and any future HTML sink are critical surfaces.

- **Project-relative paths reject leading-dash components.** `validate_project_relative_path` (`project.rs`) rejects any path component starting with `-`. `project.rootFile` flows into latexmk/pdflatex/tectonic/typst as a positional argument; a file named `-shell-escape` or `-output-directory=…` would otherwise be parsed as a flag (argument injection → RCE-adjacent). Keep this guard; don't bypass it with raw absolute-path IPC.
- **Project metadata is validated on write, not only on read.** `project::write_project` validates `rootFile` with `validate_project_relative_path()` before persisting `.typeward/project.json`, so imports/templates cannot return an unsafe in-memory `Project` that only fails later on reopen or compile.
- **Renderer-supplied project roots are gated to opened projects.** Custom file IPC validates paths relative to whatever root the webview supplies, which alone would let XSS read/write/compile anywhere (e.g. `~/.ssh`). `project.rs` keeps a registry of roots the user actually opened — `register_root` is called ONLY from the `open_project`/`list_projects`/`create_project`/`import_project_folder` paths after those paths prove the root is either already registered or under the configured projects root — and `read/write_project_*`, `set_project_integrations`, compile, snapshots, synctex, and `watch_project` all gate on `is_registered_root`. The configured `projectsRoot` is validated under Documents at the settings boundary; brand-new clone/init destinations require `is_new_path_under_projects_root`. Existing-repo git ops require a registered root. Don't add a project-root IPC without one of these gates.
- **Subprocesses spawn `which`-resolved absolute paths, never bare names.** `Command::new("latexmk"/"pdflatex"/"tectonic"/"typst"/"texlab"/"tinymist"/"synctex")` + `current_dir(project)` let Windows' `CreateProcess` resolve the program against the *project* directory first, so a planted `typst.exe` in a malicious project would run (binary planting → RCE). Compile (`compile.rs`), LSP (`lsp.rs`), and SyncTeX (`synctex.rs`) resolve through the single `detect::resolve_program(name)` helper (which runs with the app CWD, not the project) and spawn the returned absolute path. The Tectonic sidecar is already safe (Tauri hands it the bundled absolute path). Keep this; route new spawns through `detect::resolve_program` — don't reintroduce bare-name spawns or scattered `which::which` calls.
- **Project writes must not follow symlinks.** `write_project_binary_file` rejects a symlink leaf before writing (`resolve_project_write_path` only canonicalizes the parent). Text writes use `fs_ops::atomic_write`, which creates unpredictable temp files with `create_new` before rename so a malicious project cannot pre-plant `.name.tmp` as a symlink and redirect the write outside the project.
- **The outbound allowlist is enforced on every redirect hop, not just the initial URL.** `http::allowlist_redirect_policy()` re-validates scheme+host on each 3xx and is wired into the shared `http.rs` client AND the per-stream AI client (`ai/streaming.rs`). A new `reqwest::Client` reaching third parties must install this policy (or `Policy::none()`); the default follows up to 10 redirects and would turn an allowlisted open-redirect into an SSRF primitive.
- **OAuth endpoints are provider allowlisted.** `oauth_begin` validates both authorization and token endpoints against a hardcoded host+path table before opening the browser or exchanging a code — since the Dropbox removal that table is exactly `api.mendeley.com/oauth/authorize` and `api.mendeley.com/oauth/token`, so a new provider needs an entry there, not a relaxation; extra auth params cannot override PKCE core fields (`redirect_uri`, `state`, `code_challenge`, etc.). Token POST redirects stay disabled and successful token bodies are capped before parsing. Token-bearing response bodies are never echoed into error strings (they would leak into `telemetry.log`).
- **Cloud `.typeward` guard is case-insensitive at any path depth.** `normalizeRemoteRelPath` (`cloud/core/paths.ts`) rejects any segment equal to `.typeward` case-insensitively — on Windows/macOS a remote file named `.Typeward/...` would otherwise overwrite snapshots / the sync cursor / the id↔path map.
- **Zip/template import limits.** Overleaf zip extraction caps entries (5k) and total uncompressed bytes (500 MB) as a decompression-bomb guard; zip entries reject symlinks, internal `.typeward`/`.git` paths, parent traversal, absolute paths, and leading-dash components. `template_id` is rejected if it contains path separators or `..` before being joined onto the templates root; template manifests and file paths reuse project-relative validation, skip internal dirs, and refuse symlink-backed source files.
- **IPC readers and subprocess bridges are bounded.** LSP `Content-Length` frames are capped before allocation, project text/binary reads have IPC size caps, source-bundle export streams files into the zip instead of buffering whole files, SyncTeX IPC validates source/PDF paths under the active project root, autosave recovery skips symlinked snapshots, and AI streams cap error bodies plus unterminated event buffers.
- **Telemetry fields are length-capped** (`summary` 2k, `detail` 16k chars, truncated on a char boundary) so a frontend loop can't amplify the JSONL log.
- **texlive-wasm walker includes `.typeward`** (only `.git`/`node_modules`/`build`/`out`/`dist` are pruned) so `.typeward/citations/library.bib` resolves on mobile — this is the documented aggregator invariant.

**Known gaps deferred from the 2026-06-10 audit (not yet fixed — verify before relying on them):**
- **Minor LSP robustness** — duplicate `autocompletion()` config (base config + LSP extension both install it) and best-effort `notify` ordering across async invokes (audit L2/L4) remain. Low impact.

**Fixed in the 2026-06-10 follow-up pass** (so they're not re-flagged): watcher now coalesces bursts on a 150ms window and drops `.typeward/`/`.git/` churn at the Rust source (frontend filter is per-path, not whole-batch); OAuth loopback server shuts down on wait-timeout (`PendingFlow.shutdown_server`); HTTP/binary response bodies are size-capped via a streaming read (`read_body_capped`); the LSP completion source flushes the pending debounced `didChange` before querying; the editor remounts when the LSP session attaches or grammar toggles (`editorKey` memo in `text-shell.tsx`); a dead LSP server (crash/EOF) drops its handle and emits `lsp:<id>:closed`, so the frontend rejects in-flight requests immediately instead of waiting the 8s timeout (`wrap()` `onClose`).

**Fixed in the 2026-06-11 audit/remediation pass** (so they're not re-flagged): project writes validate unsafe `rootFile` values before persistence; text atomic writes no longer use a predictable temp path that could be pre-planted as a symlink; autosave recovery skips symlinked snapshots; Overleaf/template import rejects symlinks, internal dirs, leading-dash entries, and empty sanitized project names; OAuth authorization/token endpoints are provider allowlisted and token bodies are capped; AI stream ids/buffers are bounded; LSP frame allocation is capped; SyncTeX IPC validates project-contained paths; local git IPC rejects non-HTTPS remotes; cloud sync now persists per-file rev/hash state and detects concurrent edits without mtime-only comparisons, including remote-delete vs local-edit preservation.

**Fixed in the 2026-06-14 audit/remediation pass** (so they're not re-flagged): renderer-supplied roots are gated to opened projects (registry in `project.rs`; see the invariant above) and git clone/init destinations to the projects root; compile/LSP/SyncTeX spawn `which`-resolved absolute paths instead of bare names (Windows binary-planting RCE); cloned repos get a detected `.typeward/project.json` via `import_project_folder` so they appear in the library (`discover_root_file`: main.tex → first `.tex` → first `.typ`); cloud-backed project creation seeds the cache from existing remote content first (`SyncEngine.seedFromRemote` downloads files + records sync-state + persists the cursor) and only writes a starter when the remote is empty; the Dropbox provider preserved original path casing for local files so case-sensitive `\includegraphics` paths survive (moot since that provider was removed 2026-08-05, but the casing requirement binds any future provider whose API normalizes paths); sync conflict detection uses SHA-256 instead of a 32-bit FNV hash; and the esbuild advisory (GHSA-gv7w-rqvm-qjhr) was resolved by upgrading Vite 6→8 (Vite 8 uses Rolldown + Oxc and no longer depends on esbuild). Vite 8 needs Node `^20.19 || >=22.12`.
