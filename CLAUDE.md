# Typeward — Claude Code project notes

Multiplatform editor app similar to Overleaf, format-agnostic: LaTeX and Typst, with live `.md` file preview. Targets desktop (Win/Mac/Linux) and tablets (iPadOS, Android tablets — no phones). Local-first; cloud sync and real-time collaboration are future phases. (Jupyter `.ipynb`, Quarto, R Markdown, and Markdown-as-project are out of scope.)

## Where to look first

- **Plan**: `./plan.md` — full stack rationale, architectural seams, phased build, verification.
- **Designs**: `./design_files/` — HTML/CSS/JS prototypes from claude.ai/design. **Source of truth for visuals.** Don't render in a browser; read the source. JSX files are React reference only — port to idiomatic Solid (signals over hooks, no `React.Children`).

## Architecture seams — read before adding format-specific code

- **Integrations module** (`src/integrations/`, `src-tauri/src/integrations/`) — the substrate every third-party integration plugs into. Provider interfaces (`CitationProvider`, `CloudFsProvider`, `AiProvider`, `GrammarProvider`, `TemplateProvider`) live in `src/integrations/types.ts`. Each category has its own registry + init module that watches `integrationsSettings()` and registers providers reactively (`references/init.ts`, `cloud/init.ts`, `ai/init.ts`). `App.tsx` wires the inits at boot alongside `bootCoreCommands()`. Shared Rust primitives: `integrations::credentials` (OS keyring, service prefix `typeward.<provider>`, `credential_exists` for UI checks), `integrations::http` (`http_request` / `http_request_bytes` — allowlisted outbound funnel; `authRef` secrets are resolved from keyring inside Rust and bound to expected hosts), `integrations::oauth` (PKCE + `axum` loopback callback on `127.0.0.1:0`).
- **Entitlement gate** (`src/integrations/entitlements.ts`, `src/components/entitlement/FeatureGate.tsx`) — every paid-tier surface wraps in `<FeatureGate feature="integrations.x.y">` and command/init paths use `assertEntitlement()` / `hasEntitlement()`. **Pricing model (repriced 2026-07-08): Free is the core LaTeX editor** — editing (tabs/LSP/vim/palette/focus mode), LaTeX compiling on every engine, PDF preview + SyncTeX, folder projects, built-in templates, autosave/recovery, PDF + source-zip export, all themes incl. custom JSON, `.md` preview; no account needed. **Everything else is Pro**: Typst support (`formats.typst` — compile/create/tinymist are the enforcement points; free users can still *open* `.typ` files), all reference integrations (incl. local Zotero + DOI lookup), all VCS (git, GitHub, Overleaf import), all AI (incl. local Ollama), Harper grammar, cloud sync, and custom templates (`templates.custom.max` is `'0'` on free / `'unlimited'` on pro). The fallback source grants only the explicit free matrix (`templates.builtin.free`) and defaults closed for everything else; Supabase swaps in the subscription-backed source via `setEntitlementSource()`. **Locked features render nothing** (product decision 2026-06-12): `FeatureGate`'s default fallback is null and the old `UpgradePrompt` component is deleted — don't reintroduce upgrade chrome on lower tiers. A Settings integrations category with no entitled key hides entirely (nav row + card — the `*Entitled()` helpers exported from `IntegrationsPanel.tsx`).
- **`EditorAdapter`** (`src/adapters/<format>/`) — per-format glue: compile delegate + commands (the interface's `previewKind`/`cmExtensions`/`languageId` members are optional/vestigial — kept for a test fake, not consumed). Two concrete impls today: `LatexAdapter` (`compile_latex` → latexmk/pdflatex or Tectonic), `TypstAdapter` (`compile_typst` → native typst CLI). Each calls IPC through the leaf `src/commands/compile-runner.ts` (which breaks the old adapters↔actions import cycle). The format → adapter mapping is a **single source**: `adapterFor()` in `src/commands/actions.ts`, imported by `EditorScreen` (the former duplicate `adapterForFormat()` was removed 2026-07-02). Per-file/per-format dispatch tables live in `src/adapters/languages.ts` (extension→language, language→LSP/grammar) and `src/adapters/format-tables.ts` (prose facts, snippets); LaTeX-specific SyncTeX machinery lives in `src/adapters/latex/synctex.ts`. The aspirational `src/providers/` CompileProvider/PreviewProvider/LspProvider interfaces were deleted 2026-07-02 (`src/providers/compile/texlive-wasm-provider.ts` remains as the mobile engine).
- **Markdown files** — when the active editor tab is a `.md` file, the right pane swaps from `<PdfViewer>` to `<MarkdownPreview>` (markdown-it + local KaTeX renderer + DOMPurify; lives at `src/components/preview/MarkdownPreview.tsx`). Sandboxed HTML render with guarded relative-asset rewrite against the active file's directory; direct `file:` URLs, parent traversal, absolute paths, and unknown schemes are rejected. Debounced ~80ms. Does not participate in compile. See `docs/superpowers/specs/2026-05-20-narrow-formats-md-preview-design.md` and `docs/ntb_feature.md` for the removal rationale.
- **`CommandRegistry`** (`src/commands/`) — wired through end-to-end. `bootCoreCommands()` runs at app startup; adapter commands register on project load (`EditorScreen`) and unregister on cleanup. The shared `<CommandPalette />` rendered at App root reads from `commands()` directly. Global shortcuts (`Mod+K`, `Mod+N`, `Mod+,`, `Mod+S`, format-specific compile) dispatch through `src/commands/keyboard.ts` — CodeMirror no longer hardcodes `Mod-s` / `Mod-Enter`. Save/compile orchestration lives in `src/commands/actions.ts` (single point that maps `project.format` → adapter). Editor-scoped commands gate on focus being inside `.cm-content` or `[data-editor-shell]`.
- **LSP transport** (`src/lib/lsp/client.ts` raw + `wrap()` JSON-RPC wrapper, `src/lib/lsp/cm6.ts` CM6 integration, `src/stores/lsp-store.ts`) — Rust owns child processes (`src-tauri/src/lsp.rs`); frontend talks over Tauri **event channels** (`emit`/`listen`), not `invoke` for streaming traffic. `invoke` is only used for `start_lsp` / `stop_lsp` / `send_lsp_message` lifecycle and outbound writes. **We hand-rolled the CM6 binding** rather than using `codemirror-languageserver` (that package is coupled to `@open-rpc/client-js` WebSocket transport).
- **Unified file watcher** (`src-tauri/src/watcher.rs`, `src/lib/watcher/client.ts`, `src/stores/watcher-store.ts`) — single `notify` service, frontend `fsVersion` signal bumps on each event, FileTree reads it as a resource key. `.typeward/` paths are filtered to avoid autosave feedback loops.
- **Autosave** (`src/lib/autosave/index.ts`, `src-tauri/src/autosave.rs`) — debounced 500ms; snapshots to `<project>/.typeward/snapshots/<rel>.snap`; `RecoveryDialog` shows orphans on project open.
- **Telemetry** (`src/lib/telemetry/index.ts`, `src-tauri/src/telemetry.rs`) — Rust panic hook + frontend `error`/`unhandledrejection` → JSONL log at `<app_data>/telemetry.log`. Capture only; no submission UI.
- **Sentry** (`src/lib/sentry.ts`, added 2026-07-06; opt-in gate added same day) — frontend crash/error reporting via `@sentry/browser` (NOT `@sentry/solid`: its `@solidjs/router` peer caps at ^0.15, we're on 0.16; the wrapper only adds a router integration + ErrorBoundary HOC we don't use). **Strict egress opt-in:** `installSentryGate()` (`src/lib/sentry-gate.ts`, called from App.tsx boot) watches the persisted `privacy.shareCrashReports` setting (default OFF; toggle in Settings → Security → Privacy) and dynamic-imports + inits the SDK only when enabled — opted-out users never fetch the chunk; toggling off calls `shutdownSentry()` (flush + disable). Don't reintroduce an unconditional boot kick, and keep all imports dynamic so the ~275 KB SDK chunk stays off the `check:bundle` boot path. Tracing + Replay enabled when active (replay masks all text by default — editor content must stay masked); `tracePropagationTargets: []` on purpose (no first-party HTTP backend; trace headers on Supabase/provider requests risk CORS preflights). Ingest host is allowlisted in both CSPs (`connect-src https://*.ingest.de.sentry.io`); Replay's worker rides the existing `worker-src blob:`. App-shell ErrorBoundary crashes are forwarded explicitly (`reportCrash`, gated on the same setting) since Solid-caught errors never hit `window.onerror`. Dev-only palette command `dev.sentryTest` ("Send Sentry test error") verifies the end-to-end pipeline (toasts a hint when the opt-in is off). Local telemetry.log capture is unchanged, always on, and remains the pre-init safety net. **Source maps:** `@sentry/vite-plugin` in vite.config.ts, active only when `SENTRY_AUTH_TOKEN` is set in `.env.sentry-build-plugin` (gitignored; see .env.example) — emits `hidden` sourcemaps, symbolication matches via injected Debug IDs (release auto-named from the git SHA), and maps are deleted from dist/ after upload because `tauri build` ships dist/ verbatim (a leftover .map = full source leak). No token → no maps generated at all. Upload failures warn but don't fail the build — watch for `[sentry-vite-plugin] Error` lines. Verified compatible with Rolldown-Vite (Vite 8).
- **Responsive layout** (`src/stores/viewport-store.ts`, `src/components/layout/PaneSwitcher.tsx`, `src/lib/gestures.ts`) — `viewportMode()` flips at the 1024px breakpoint. `TextShell` keeps a desktop `DesktopLayout` (corvu Resizable, unchanged) and a tablet variant that swaps in `<Switch>`-based single-pane rendering, the `PaneSwitcher` segmented control, the slide-up `LogsSheet`, and a swipe listener. `setActivePane()` is the public lever for pane navigation; treat `cyclePane()` as gesture-only. Don't add fixed-width assumptions in shells — guard behind `isTabletViewport()` instead.
- **texlive-wasm CompileProvider** (`src/providers/compile/texlive-wasm-provider.ts`) — mobile-only Web Worker LaTeX engine via `texlive-wasm` (file:../texlive-wasm, Typeward's MIT-licensed sibling repo). Selected when `compileEngine() === "texlive-wasm"`; not available on desktop. `LatexAdapter.compile()` dynamic-imports the provider so the WASM bridge isn't pulled into desktop bundles when unused. Assets live in `src-tauri/resources/texlive-wasm/` and are fetched once with `npx texlive-wasm download-assets ./src-tauri/resources/texlive-wasm`; the provider probes the asset before init and returns an actionable diagnostic when missing. Compilation goes through `latexmk()`. PDF bytes are persisted via the project-scoped `write_project_binary_file` IPC into `<project>/.typeward/build/<base>.pdf` so the existing file-path-driven PdfViewer renders it unchanged. Diagnostics route through the shared Rust parser via the `parse_latex_log_cmd` IPC. The provider walks both text dependencies (`.tex`, `.bib`, `.cls`, `.sty`, etc., read via `read_project_text_file`) and binary figures (`.png`, `.jpg`, `.jpeg`, `.pdf`, `.gif`, `.eps`, via `read_project_binary_file`); capped at 200 files / 10 MB combined.
- **Reference aggregator** (`src/integrations/references/aggregator.ts`) — `refreshLibraryBib(project)` calls `exportAllAsBibTex()` on every registered `CitationProvider` (Zotero local — Better BibTeX or Zotero 7's built-in API, Zotero Web, Mendeley), pulls in `<project>/.typeward/citations/local.bib` (DOI/arXiv lookups land here), dedupes by citation key, and writes the unified result to `<project>/.typeward/citations/library.bib`. The texlive-wasm walker auto-discovers it; texlab/tinymist see it as a normal `.bib` and provide `\cite{}` completions for free. Per-provider config lives in `IntegrationsSettings.references.{betterBibTex,zoteroWeb,mendeley}`; tokens live in the keyring under service names matching the provider id. (JabRef `.bib`-file import was removed 2026-06-13 — point Zotero at the library instead, or DOI-lookup into the project `local.bib`.)
- **Cloud sync engine** (`src/integrations/cloud/core/engine.ts`) — generic bidirectional orchestration. One `SyncEngine` per active cloud-backed project. Local cache layout: `<projectsRoot>/.remote-cache/<provider>/<projectId>/`; the cache *is* a normal Typeward project (same `.typeward/` sidecar, same watcher, same compile pipeline). Provider state under `<cache>/.typeward/integrations/<provider>/` (cursor + ID/path map + `sync-state.json`). **Pull** drains every delta page in one pass; **push** is queued from the save path — `saveActiveFile`/`saveAllDirtyFiles` call `notifyLocalSave(rootPath, relPaths)` (`cloud/init.ts`), which feeds `engine.queuePush()`; uploads coalesce on a 1.5s debounce and retry on a 15s backoff. Pull and push are serialized through one promise chain (`runExclusive`) so they never interleave on the shared cursor/cache. **Echo suppression:** each upload records its returned `rev` keyed by relPath; when the next delta replays our own write, the matching rev makes the engine skip it instead of minting a spurious `.conflict-*` sidecar. The persisted sync state records provider id/rev plus local content hash/size/mtime for each synced file; conflict detection compares remote rev changes against local hash changes instead of relying on filesystem mtime alone, and remote-delete vs local-edit preserves the local file as a `.conflict-*` sibling before removing the canonical path. The snapshot autosave does NOT push (`.typeward/` is rejected in `normalizeRemoteRelPath`). Remote relative paths are normalized before cache IO; absolute paths, parent traversal, Windows drive prefixes, NULs, and `.typeward/` targets (case-insensitive, any depth) are rejected. Conflict resolution writes the loser to `<name>.conflict-<ISO>.<ext>`; `<ConflictResolverDialog>` (reachable by clicking `<SyncStatusBadge>` when conflicts > 0) resolves them. Engine lifecycle in `cloud/init.ts` — when a project with `integrations.cloudOrigin` becomes active, the matching provider instantiates from settings and entitlement is checked before the engine starts. Provider factory `cloudProviderForAccount(ref, { projectsRoot, projectId })` in `cloud/registry.ts`.
- **AI streaming primitive** (`src-tauri/src/integrations/ai/streaming.rs`, `src/integrations/ai/stream.ts`) — one Rust task per stream, format-specific parsers in `parse_event()` (AnthropicSse / OpenAiSse / GeminiSse / OllamaNdjson). Chunks emit on a per-stream Tauri event channel `ai-stream:<streamId>`; stream ids are restricted to short ASCII `A-Z a-z 0-9 _ -` values and duplicate ids are rejected so abort handles cannot be orphaned. The frontend `aiStream(req, signal)` AsyncIterable adapter listens, yields each delta, calls `ai_stream_abort` when the AbortSignal fires. Stream URLs pass the same outbound allowlist as `http_request`; OpenAI/Anthropic/Gemini keys use `authRef` and stay in Rust. Error bodies and unterminated stream buffers are capped to avoid unbounded memory growth from attacker-controlled endpoints. All four providers (Claude/ChatGPT/Gemini/Ollama) implement the same `AiProvider` shape (`models()` + `chat(messages, opts)`); only one is active at a time per `IntegrationsSettings.ai.activeProvider` and entitlement.
- **Local git** (`src-tauri/src/integrations/vcs/git.rs`) — libgit2 via the `git2` crate, every operation wrapped in `tokio::task::spawn_blocking` because libgit2 is fully synchronous. HTTPS auth comes from the keyring under service `git.<host>` so a single GitHub device-flow sign-in covers both REST API calls (via `httpRequest` `authRef`) and libgit2's push/pull callbacks. SSH transport is out of scope; only HTTPS + PAT, and git IPC now rejects non-HTTPS remotes (`file://`, SSH URLs, scp-style remotes). `git_pull` is fast-forward only and refuses to checkout when the worktree has staged, unstaged, or untracked changes — merge commits still need a conflict UX we don't ship yet.
- **Harper grammar** (`src-tauri/src/integrations/grammar/mod.rs`, `src/lib/grammar/cm6.ts`) — Rust-native, runs in-process via `harper-core`. `grammar_check(text, file, syntax)` IPC returns diagnostics in the same shape as compile/LSP diagnostics so the existing gutter renders them without changes. CM6 linter extension via `@codemirror/lint`, debounced 400ms; up to 3 quick-fix actions per lint. Wired into the editor only when `integrations.grammar.enabled` AND the `integrations.grammar.harper` entitlement (Pro) — zero IPC when off or unentitled.
- **Templates** (`src-tauri/src/integrations/templates.rs`) — `templates_list()` merges built-ins from `<resource>/templates/` (bundled per `tauri.conf.json` `bundle.resources`) with user customs at `<app_data>/templates/custom/`. Each template ships a `template.json` manifest plus its files; `template.files[*].template = true` opts a file into Handlebars-subset `{{var}}` substitution at `template_instantiate` time. Other files copy verbatim. IDs are namespaced (`builtin:<id>` / `custom:<id>`) so short names don't collide across sources. `template_save(project, name, description)` does the reverse — captures the open project into `<app_data>/templates/custom/<id>/` (skips `.typeward/`/`.git/`/symlinks/LaTeX build junk, copies the rest verbatim, writes a `template.json` with empty `variables`/`files`). Triggered by the `core.saveTemplate` command → `<SaveTemplateDialog>` mounted at the App root via the `requestSaveTemplate` signal.
- **Supabase auth + entitlement source** (`src/integrations/supabase/`) — singleton `SupabaseClient<Database>` keyed off `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` from `.env.local`; returns `null` when missing so the app keeps working free-tier. Session bundle persists via a keyring-backed `Storage` adapter (`storage.ts` routes `get/set/removeItem` through `credential_*` IPCs under service `typeward.supabase.session`). Reactive `supabaseSession()` signal in `session.ts`. `initSupabaseEntitlements()` watches the signal and swaps the free-tier fallback `EntitlementSource` for a real one backed by the `get_entitlements()` RPC; cached/fresh async results are ignored if the user signs out or switches accounts before they resolve. The resolved snapshot caches in the keyring under `typeward.supabase.entitlements/<userId>` with a 30-day TTL for offline, plus cheap clock-tamper guards (`isSnapshotUsable`: a snapshot with `fetchedAt` in the future or read after the wall clock moved backwards past its `lastSeenWallClock` — both beyond a 5-minute skew — is treated as no cache). Exported `refreshEntitlements()` re-fetches for the current user; a window-focus listener (throttled to once per 30s) and the Settings → Account "Refresh plan" button call it. The whole chain is mounted once from `App.tsx`. Backend SQL + RLS + RPC live in the dedicated `typeward/infrastructure` repo (sibling checkout at `../infrastructure`).

## Gotchas

- **Sync Tauri commands run outside the tokio runtime.** Calling `tokio::spawn` from a sync `#[tauri::command]` panics with "no reactor running" and aborts the process (Windows reports `STATUS_STACK_BUFFER_OVERRUN` / `0xc0000409`). Mark any command that touches tokio (`spawn`, `mpsc`, `tokio::process`, etc.) as `pub async fn`. Reference: `watcher.rs::watch_project`.
- **Tauri 2 fs plugin requires explicit scope.** `fs:default` + bare `fs:allow-*` permissions don't grant access to arbitrary paths — they need an `allow` list. Project files live under `~/Documents/Typeward` by default; `capabilities/default.json` scopes plugin-fs to `$DOCUMENT/**`. Custom project IPC (`read_project_text_file` / `write_project_text_file` / `write_project_binary_file`) still validates canonical project-relative paths. **`fs:allow-read-file` (binary) is separate from `fs:allow-read-text-file`** — PDF reads need the binary one. If arbitrary out-of-Documents project roots are reintroduced, add a scoped IPC/runtime-scope story first.
- **PDF.js `RenderingCancelledException`** is benign — fired whenever a render is superseded by a newer one (e.g., on quick recompile). `PdfViewer` uses a generation counter and silently swallows it. Don't surface it as an error.
- **Custom Tauri commands bypass fs plugin scope** — project file IO must use `read_project_text_file` / `write_project_text_file` / `write_project_binary_file`, which validate project-relative paths against the canonical root. Compile commands also validate `project.rootFile`. Don't reintroduce raw absolute-path file IPC.
- **CodeMirror remount on tab switch** — `text-shell.tsx` keys CodeMirror on `activeFile().path` so the LSP gets a fresh `didOpen` per file. Don't try to swap content in place via dispatch; that breaks LSP doc tracking.
- **`@fontsource-variable/inter` + `@fontsource-variable/jetbrains-mono`** ship variable fonts (one axis file per family, plus an italic axis file). `App.tsx` imports the Inter + JetBrains Mono index and wght-italic CSS. They block initial paint in dev — biggest contributor to the pre-paint flash before `backgroundColor` in `tauri.conf.json` made the window paint in the default theme's bg on creation (`#F8F4EA` since the Daylight default; was `#0A0B0F` in the Aurora era). The boot splash in `index.html` defaults to Daylight colors and `public/boot-theme.js` (a classic script served verbatim from public/ — kept out of the Vite bundle graph so the re-tint runs before the app bundle even in release builds; external because CSP forbids inline scripts) re-tints it from the persisted theme, so dark-theme users don't get a cream flash. A previous `visible: false` + `getCurrentWindow().show()` deferred-reveal pattern was removed: it masked render-time crashes (window stayed hidden if `onMount` never fired), and the static background alone is sufficient.
- **Compile fallback chain**: `system-tex` engine tries `latexmk` first, falls back to `pdflatex` on spawn/exit failure (MiKTeX sometimes ships latexmk without a usable Perl). `tectonic` engine tries the sidecar (`binaries/tectonic-<triple>`) first, falls back to `tectonic` on PATH. Either way, the actual command + log get surfaced in the LogsDrawer's Logs tab.
- **Typst syntax highlighter is hand-rolled.** `src/adapters/typst/typst-language.ts` is a minimal CM6 `StreamLanguage` covering the visual basics (comments, strings, math, `#funcs`, headings, emphasis). It's intentionally not a full grammar — when tinymist's structured tokens become consumable through the LSP transport, prefer those over expanding this parser.
- **SyncTeX shells out to the system `synctex` CLI** (`src-tauri/src/synctex.rs`), not a Rust binding. TeX Live / MiKTeX / MacTeX all ship it; the CLI returns `Ok(None)` if not on PATH so Tectonic-only users get a graceful "no sync" rather than an error. Compile flags: `-synctex=1` for latexmk/pdflatex, `--synctex` for tectonic. Forward search wires through `requestPdfScroll(page, y)` → PdfViewer's `scrollTarget` effect. Inverse search is **double-click** on a PDF page (shift+click still works as a secondary path) → `triggerInverseSearch` → `onPageClick(page, x, y)` (coords divided by current zoom to get PDF pts) → `requestGotoSource(relPath, line)` → EditorScreen opens the file and moves the cursor via the imperative `editor-view-store` handle.
- **Linux dev hosts need `libdbus-1-dev`** for the `keyring` crate's Secret Service backend, plus `libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev` for Tauri's GTK chain. Apt one-liner: `sudo apt install -y libdbus-1-dev libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.
- **Tectonic sidecar naming** — `fetch-tectonic.mjs` downloads the musl static binary (`tectonic-x86_64-unknown-linux-musl`), but Tauri's build script looks up the rustc target triple (`tectonic-x86_64-unknown-linux-gnu` on Linux). Symlink `gnu → musl` after fetch if Tauri build complains: `ln -sf tectonic-x86_64-unknown-linux-musl tectonic-x86_64-unknown-linux-gnu` in `src-tauri/binaries/`. The musl binary works fine on glibc systems — it's statically linked.
- **OAuth client ids come from `.env`** as `VITE_<provider>_CLIENT_ID`. Mendeley / Dropbox / GitHub each need their own registered app. The code paths are valid without the env vars — sign-in just throws an actionable "register your app at <url>" error. **Dropbox/GitHub are PKCE public clients (no secret). Mendeley is the exception: a *confidential* client** — it doesn't support PKCE and exact-matches the redirect URI with no dynamic ports. So the Mendeley flow (`runOauthFlow({ clientSecret, redirectUri })` → `oauth_begin`) passes a `client_secret` (stored in the keyring under service `mendeley` account `app-secret`, entered in Settings; the token exchange uses HTTP Basic via reqwest `.basic_auth`, and the frontend refresh attaches `Authorization: Basic` via the `api.mendeley.com` raw-auth-header allowance) and a full `redirect_uri` the user pastes from their Mendeley registration (default `http://localhost:5000/callback`, persisted in `references.mendeley.redirectUri`). `oauth_begin`'s `redirect_uri` override is loopback-validated (`parse_loopback_redirect`: http + `localhost`/`127.0.0.1`/`::1` + explicit port) and binds **both** IPv4 and IPv6 loopback on that port so `localhost` resolves either way; a busy port returns an actionable error. PKCE providers (no `redirect_uri`) keep the random `127.0.0.1` port. Loopback servers are shut down via a `broadcast` channel (multiple listeners).
- **`http_request` returns text body; binary needs `http_request_bytes`** — when a cloud provider downloads/uploads file bytes, route through the binary IPC and `httpRequestBytes`. The text variant truncates non-UTF-8 payloads. Both commands enforce an outbound host/scheme allowlist; `authRef` credentials are bound to expected provider hosts and raw auth headers are rejected for metadata-only hosts.
- **Frontend keyring reads are an allowlist, not a blocklist.** `frontend_read_allowed()` (`credentials.rs`) permits the generic `credential_get` for exactly one service — `supabase.entitlements` — and rejects everything else (`CredentialError::ReadNotAllowed`). API keys and OAuth tokens are never read by the frontend: they attach in Rust via `authRef`, and the Supabase session bundle has its own dedicated `supabase_session_read` command. Use `credential_exists` for UI state. (Corrected 2026-07-02: the code was already a strict allowlist; the prior "blocklist with per-provider exceptions" wording was stale.)
- **`git_pull` is fast-forward only and requires a clean worktree.** Merge commits surface as an error verbatim — the user resolves by hand for now. The conflict surface that would handle non-fast-forward pulls is the same gap that keeps SSH transport out of scope.
- **OS keyring on Linux blocks on D-Bus.** All `credential_*` IPC handlers spawn-blocking around the sync keyring API so the Tokio runtime (LSP / watcher / autosave / cloud sync) doesn't park during a Secret Service unlock prompt. New keyring callers should follow the same `tokio::task::spawn_blocking` pattern.
- **Windows Credential Manager caps blobs at 2560 bytes** (≈1280 chars after UTF-16 encoding). Anything larger silently fails to persist — this broke Supabase session storage (the JWT bundle is ~4KB) and surfaced as a useless "[object Object]" login error. Large frontend-side credentials must go through `src/integrations/auth/chunked.ts` (`get/set/deleteChunkedCredential` — splits into ≤1024-char parts plus a `__typeward_chunks__:<n>` marker record). This is **frontend-only**: secrets that Rust reads via `authRef` must stay un-chunked single records, so keep them short (API keys are fine). Use `describeIpcError` from `src/lib/errors.ts` (the single canonical normalizer; `chunked.ts` and `Toaster`'s `errorText` re-export it) instead of `String(e)` when surfacing IPC errors — never `[object Object]`. Rust commands now reject with a plain Display string (see the error-contract invariant), so a string rejection is the message verbatim.
- **CodeMirror's `defaultKeymap` binds `Mod-Enter` to `insertBlankLine`.** We filter it out in `CodeMirror.tsx` (`defaultKeymap.filter((b) => b.key !== "Mod-Enter")`) because the global keyboard router also dispatches Mod+Enter as compile — without the filter every compile shortcut also injected a blank line into the doc. Any new keymap source must not reintroduce a `Mod-Enter` binding.
- **Persisted settings enums are validated at the load boundary.** `settings-store.ts` runs every enum-shaped field (theme, accent, density, view, sort) through `validEnum(raw, allowed, fallback)` when reading `settings.json`, so stale values from removed variants (e.g. the deleted `obsidian`/`graphite` themes) degrade to defaults instead of rendering an unthemed app. Register any new persisted enum there.
- **Zotero integration has two local paths.** The provider probes Better BibTeX first (`localhost:23119/better-bibtex/…`), then falls back to Zotero 7's built-in local API (`127.0.0.1:23119/api/users/0/items?format=bibtex`, paginated via the `Total-Results` header). BBT is optional — plain Zotero 7 with "Allow other applications" enabled is enough. Don't make BBT-specific endpoints a hard requirement. **There is no library-id setting (removed 2026-06-15):** the provider auto-discovers all libraries — the personal library plus every group library via `/api/users/0/groups` — and exports each (BBT keys for the personal library at `library?/1/library.bib`, the local API for groups since BBT's internal library ids don't match the public group ids). Each entry is tagged with its library name (`Citation.library`). The References panel has **two** selectors (product decision 2026-06-21, after a 3-selector split was rejected as too many): the reference **manager** (book/`BookMarked` icon — instant, from the registry) and one combined **library/folder/subfolder tree** (`Folder` icon throughout) showing the manager's libraries with their collections nested. Libraries load fast (`listLibraryNodes`, no collection discovery) and render immediately; the manager's folders (`listCollections` per library, in parallel) **merge into the tree as they arrive**, re-rooted under their library — so the library list isn't blocked on folder lookups (the old all-collections-up-front discovery was the "loads slow" cost). Selecting any node (a library or a collection) lists its citations. **Only the selected provider is queried** — the panel does NOT fan out `listLibraryNodes`/`searchLibrary` across all providers (that was the open-time slowness, esp. for networked Zotero Web/Mendeley). The manager dropdown only OFFERS providers whose `status()` resolves `ready` (probed in parallel via `availableRes`, cached) — unreachable ones are hidden; selection validates against the registered list to avoid flicker. The source control's **presence** is gated on the *registered* count (`providers().length > 1`, synchronous) — NOT the async availability count — so it appears together with the library selector instead of popping in a beat later; availability only filters the dropdown options + auto-select (single reachable). Once chosen, the manager selector **collapses to a book icon** inline with the tree to save space (`FlatSelect compact`); the combined tree is `TreeSelect` (`Folder` icon). Persistence is two localStorage maps: `typeward.refs-provider` (`[root]→providerId`) and `typeward.refs-library` (`[root::providerId]→nodeId`, the browse target — a library or collection id), so each manager remembers its last node. Auto-select picks the first library, but defers when a (possibly-folder) selection was persisted so it can validate once collections load rather than being clobbered. Neither narrows the aggregated `library.bib` (which still carries every provider's full catalog). Providers expose two optional methods returning `LibraryNode` (`{id,name,parentId?,kind:"library"|"collection"}`): `listLibraryNodes()` (top-level libraries, fast) and `listCollections(libraryNodeId)` (that library's folders, lazy; top-level collections have `parentId` undefined). **All three providers implement it** via the shared `zotero/nodes.ts` helpers (`libNodeId`/`collNodeId`/`resolveNode`, node-id grammar `user | group/<gid> | <lib>/c/<collKey>`, plus `isValidKey` — `[A-Za-z0-9_-]{1,64}`, wide enough for Mendeley's UUID folder ids, still blocks `/`/`.`/whitespace). **Mendeley** (`mendeley/provider.ts`) exposes the personal library (`listLibraryNodes`) + its **folders** via `listCollections` (Mendeley collections, nested via `parent_id`, from `/folders`). **Mendeley API gotchas (got these wrong twice):** pagination is opaque **marker/cursor** only — follow the `Link: rel="next"` URL verbatim (`parseNextLink`), there is NO `offset`/`start` param (`limit` max 500); and `/documents` has **no `folder_id` filter** — a folder's contents come from `GET /folders/{id}/documents` (returns doc *ids* only, no BibTeX), so per-folder BibTeX = list ids then fetch each `GET /documents/{id}?view=bib` (bounded concurrency, cap 500). Search is in-process over the BibTeX so inserted keys are real citekeys (the old JSON path inserted Mendeley `doc.id`, which never matched `library.bib` — a latent bug fixed 2026-06-21). A provider without `listLibraryNodes` would still fall back to one node with `id===displayName`. The **web** provider namespaces its ids with a `zw:` prefix so they never collide with the local provider's bare ids when both are configured. `searchLibrary(query, nodeId?)` filters to the chosen node (in-process over a cached, TTL'd BibTeX export tagged by stable `libId` — not the non-unique display name) and returns `[]` for ids it doesn't own. **Browsing exports only the selected library/collection, not the whole catalog:** the library branch uses a per-`libId` `libEntriesCache` (and collections a per-node `collCache`); the full multi-library `refresh()` is reserved for `exportAllAsBibTex` → `library.bib`. `listLibraryNodes` is libraries-only (fast); `listCollections(libraryId)` discovers one library's collections — the panel calls it for every library in parallel and merges the results into the combined tree. **`listCollections` is deliberately NOT cached** (fetched fresh on every panel open / refresh) so the folder tree always mirrors the live Zotero/Mendeley structure — deleted folders must not linger; discovery is one cheap request while the heavy citation exports stay cached. **Trashed Zotero collections are pruned client-side:** Zotero's `/collections` API returns trashed collections (`deleted:true`) AND their descendants (it has no `includeTrashed` filter, unlike `/items`), so the desktop/web UI hides them but the API doesn't — `pruneTrashedCollections` (`zotero/nodes.ts`) drops the whole trashed subtree (cycle-safe). Without it, folders deleted in Zotero kept showing in the picker. Multi-page BibTeX exports fetch the first page then the rest **concurrently** (`mapLimit`, cap 5) — Mendeley stays sequential (opaque cursor). Entry/library/node caches are TTL'd (60s); `invalidate()` (panel Refresh) clears them. **Collection keys stay consistent with `library.bib`:** personal-library collections export via the BBT collection pull (`/better-bibtex/collection?/1/<collKey>.bibtex`) when BBT is up (BBT keys), and via the local/web API (`/collections/<collKey>/items/top?format=bibtex`) for group collections or when BBT is absent — mirroring `exportLibrary`'s per-library choice so an inserted `\cite{key}` always resolves. (The web provider has no BBT, so all its libraries/collections use the web API uniformly — this also fixed a latent bug where web search inserted Zotero item keys instead of BibTeX citekeys.) `betterBibTex` settings are now just `{ enabled }`; a stale `libraryId` in old settings.json is ignored on read.
- **Supabase publishable keys vs legacy anon JWTs.** `sb_publishable_…` is Supabase's post-Oct-2025 API key format that replaces the JWT-shaped `anon` key. `supabase-js` ≥2.45 accepts both transparently; older versions silently fall back to anonymous and every authenticated request 401s. Pin the dep ≥2.106 (our lockfile does). Service-role keys take the matching `sb_secret_…` shape and **must never** land in `.env.local` — only in `../infrastructure`'s edge functions.
- **`database.types.ts` is generated — don't hand-edit it.** Since 2026-07-08 the infrastructure repo's `deploy-staging.yml` regenerates it (`supabase gen types typescript`) after every staging migration deploy and opens a PR here on drift; merge that PR rather than patching by hand. The generated file includes the `stripe_*` columns and billing tables — TypeScript types grant nothing, RLS is the security boundary. (If a hand-patch is ever unavoidable: each table entry needs `Row`, `Insert`, `Update`, AND `Relationships`, and the public schema needs `Tables`/`Views`/`Functions`/`Enums`/`CompositeTypes`, or supabase-js narrows row types to `never`.)
- **Entitlement sources default closed for unknown keys.** The free fallback only grants the explicit free matrix; the Supabase source returns `false` when `get_entitlements()` returns an unknown feature key. Add every new gated key to `seed.sql`'s `entitlements_map` block — otherwise the feature silently locks for signed-in users on the next deploy. The canonical list is `KNOWN_ENTITLEMENT_KEYS` (17 keys) mirrored by `seed.sql`'s matrix in `../infrastructure`.

## Security invariants (established 2026-06-10 audit)

Threat model: local user is trusted; adversaries are malicious project content (cloned repos, Overleaf zips, custom templates, `.md`/`.tex`/`.bib`/log files) and attacker-controlled remote content (cloud-synced files, Zotero/Mendeley records, git remotes, AI endpoints). Webview XSS = arbitrary IPC = file write + process spawn, so the `.md` preview and any future HTML sink are critical surfaces.

- **Project-relative paths reject leading-dash components.** `validate_project_relative_path` (`project.rs`) rejects any path component starting with `-`. `project.rootFile` flows into latexmk/pdflatex/tectonic/typst as a positional argument; a file named `-shell-escape` or `-output-directory=…` would otherwise be parsed as a flag (argument injection → RCE-adjacent). Keep this guard; don't bypass it with raw absolute-path IPC.
- **Project metadata is validated on write, not only on read.** `project::write_project` validates `rootFile` with `validate_project_relative_path()` before persisting `.typeward/project.json`, so imports/templates cannot return an unsafe in-memory `Project` that only fails later on reopen or compile.
- **Renderer-supplied project roots are gated to opened projects.** Custom file IPC validates paths relative to whatever root the webview supplies, which alone would let XSS read/write/compile anywhere (e.g. `~/.ssh`). `project.rs` keeps a registry of roots the user actually opened — `register_root` is called ONLY from the `open_project`/`list_projects`/`create_project`/`import_project_folder` paths after those paths prove the root is either already registered or under the configured projects root — and `read/write_project_*`, `set_project_integrations`, compile, snapshots, synctex, and `watch_project` all gate on `is_registered_root`. The configured `projectsRoot` is validated under Documents at the settings boundary; brand-new clone/init destinations require `is_new_path_under_projects_root`. Existing-repo git ops require a registered root. Don't add a project-root IPC without one of these gates.
- **Subprocesses spawn `which`-resolved absolute paths, never bare names.** `Command::new("latexmk"/"pdflatex"/"tectonic"/"typst"/"texlab"/"tinymist"/"synctex")` + `current_dir(project)` let Windows' `CreateProcess` resolve the program against the *project* directory first, so a planted `typst.exe` in a malicious project would run (binary planting → RCE). Compile (`compile.rs`), LSP (`lsp.rs`), and SyncTeX (`synctex.rs`) resolve through the single `detect::resolve_program(name)` helper (which runs with the app CWD, not the project) and spawn the returned absolute path. The Tectonic sidecar is already safe (Tauri hands it the bundled absolute path). Keep this; route new spawns through `detect::resolve_program` — don't reintroduce bare-name spawns or scattered `which::which` calls.
- **Project writes must not follow symlinks.** `write_project_binary_file` rejects a symlink leaf before writing (`resolve_project_write_path` only canonicalizes the parent). Text writes use `fs_ops::atomic_write`, which creates unpredictable temp files with `create_new` before rename so a malicious project cannot pre-plant `.name.tmp` as a symlink and redirect the write outside the project.
- **The outbound allowlist is enforced on every redirect hop, not just the initial URL.** `http::allowlist_redirect_policy()` re-validates scheme+host on each 3xx and is wired into the shared `http.rs` client AND the per-stream AI client (`ai/streaming.rs`). Build outbound clients through the single `http::outbound_client_builder()` constructor (2026-07-02), which always installs this policy; a new hand-rolled `reqwest::Client` reaching third parties must install the policy (or `Policy::none()`) itself — the default follows up to 10 redirects and would turn an allowlisted open-redirect into an SSRF primitive. (WebDAV keeps its own dedicated SSRF-screened client, which also installs the policy.)
- **IPC error contract: commands reject with a plain Display string, not a serialized enum.** Every `#[tauri::command]` maps its typed error to `String` at the boundary (`.map_err(|e| e.to_string())`); internal fns keep their `thiserror` types. This preserves the authored message across the bridge (a serialized enum object surfaced as `[object Object]`). The frontend's single normalizer is `describeIpcError` in `src/lib/errors.ts` (treats a string rejection as the message; unwraps `Error`/`{message}`/`{error}`; never returns `[object Object]`). `recordError` is bulletproof (a synchronous throw from the IPC layer can't break the caller). Never put secrets/tokens/response bodies in error strings.
- **Git and the `.typeward` sidecar compose via `.git/info/exclude`.** `project::ensure_sidecar_git_excluded(root)` writes `.typeward/` into `.git/info/exclude` (never the user's `.gitignore`) on init/clone/open/import; `git.rs::is_sidecar_path()` additionally filters `.typeward` out of `git_status`, `ensure_clean_worktree` (so pulls aren't permanently DirtyWorktree-blocked), and the `git_stage` add-all default (so snapshots/build/reviews are never committed). Mirrors the cloud engine's `normalizeRemoteRelPath` guard. Keep both layers.
- **Remote relative paths are a branded type.** `normalizeRemoteRelPath` (`cloud/core/paths.ts`) returns an opaque `NormalizedRelPath` that the cache-IO functions require, so a raw string can't reach cache IO without passing the funnel (the `.typeward`/traversal/absolute/drive rejections). Don't cast around the brand.
- **WebDAV uses a dedicated, account-gated, SSRF-screened outbound client — NOT the shared `http_request` allowlist.** A WebDAV server is a user-supplied host, so `integrations/webdav.rs` builds its own per-request `reqwest` client: it resolves the host, screens every resolved IP against a deny-table (loopback / link-local / cloud-metadata `169.254.169.254`+`fd00:ec2::254` / `0.0.0.0` blocked unconditionally; RFC1918 / ULA / CGNAT blocked unless the account opted into a private/LAN host), pins the connection to the vetted IP (resolve-then-pin, anti-rebinding), ALSO screens numeric-literal hosts (decimal/hex/octal/IPv4-mapped — a literal host bypasses the resolver, the Vaultwarden bug class), and follows only same-host https redirects. A host is accepted only if it matches a persisted, user-confirmed WebDAV account (allowlist-by-account — same shape as renderer-roots-gated-to-opened-projects). PROPFIND multistatus XML (attacker-controlled) is parsed in Rust with `quick-xml` (non-validating → immune to XXE and entity-expansion), never the webview DOMParser. The Basic-auth password lives in keyring service `webdav`; username + base URL live in `cloud.accounts`. Don't route WebDAV through the fixed-allowlist funnel or relax `allowed_https_host` for user hosts.
- **OAuth endpoints are provider allowlisted.** `oauth_begin` validates both authorization and token endpoints against the known Dropbox/Mendeley hosts before opening the browser or exchanging a code; extra auth params cannot override PKCE core fields (`redirect_uri`, `state`, `code_challenge`, etc.). The optional confidential-client `redirect_uri` override is loopback-only (`parse_loopback_redirect` rejects non-loopback hosts, non-http, and missing ports) so the renderer can't redirect the auth code to an external host. Token POST redirects stay disabled and successful token bodies are capped before parsing. Token-bearing response bodies — and the client secret — are never echoed into error strings (they would leak into `telemetry.log`).
- **Cloud `.typeward` guard is case-insensitive at any path depth.** `normalizeRemoteRelPath` (`cloud/core/paths.ts`) rejects any segment equal to `.typeward` case-insensitively — on Windows/macOS a remote file named `.Typeward/...` would otherwise overwrite snapshots / the sync cursor / the id↔path map.
- **Zip/template import limits.** Overleaf zip extraction caps entries (5k) and total uncompressed bytes (500 MB) as a decompression-bomb guard; zip entries reject symlinks, internal `.typeward`/`.git` paths, parent traversal, absolute paths, and leading-dash components. `template_id` is rejected if it contains path separators or `..` before being joined onto the templates root; template manifests and file paths reuse project-relative validation, skip internal dirs, and refuse symlink-backed source files.
- **IPC readers and subprocess bridges are bounded.** LSP `Content-Length` frames are capped before allocation, project text/binary reads have IPC size caps, source-bundle export streams files into the zip instead of buffering whole files, SyncTeX IPC validates source/PDF paths under the active project root, autosave recovery skips symlinked snapshots, and AI streams cap error bodies plus unterminated event buffers.
- **Telemetry fields are length-capped** (`summary` 2k, `detail` 16k chars, truncated on a char boundary) so a frontend loop can't amplify the JSONL log.
- **texlive-wasm walker includes `.typeward`** (only `.git`/`node_modules`/`build`/`out`/`dist` are pruned) so `.typeward/citations/library.bib` resolves on mobile — this is the documented aggregator invariant.

## Conventions

- **Use npm**, not pnpm or yarn (user preference).
- **No emojis** in code, files, or commit messages unless explicitly asked.
- **No `Co-Authored-By:` trailers on commits** — the local git identity is the user; don't append Claude or any assistant as co-author. Applies to direct commits and to any subagent instructed to commit.
- **No new docs/README files** unless requested.
- **No comments explaining what code does** — only *why*, when non-obvious. Don't reference tasks/PRs/callers in comments.
- **Designs are visual truth** — port HTML output, not the prototype's React structure.
- **Themes** swap via `<html data-theme="...">` and `<html data-accent="...">`. Exactly four ship: **Daylight** (default — t1 Desk Lamp light, tuned to `design_files/sample_identity.txt`: ivory paper, charcoal ink, near-black primary, brass selection, seal-red errors), **Lamplight** (t1 dark), **Aurora** (`tokens.css` `:root` baseline, no `data-theme`), **Paper**. Per-theme `--syntax-*` tokens drive CodeMirror colors; `--color-accent-fg` is the text color on `.accent-grad` surfaces; `--color-text-selection` is the selection wash. User **custom themes** (JSON in `<app_data>/themes/`, validated in `themes.rs`) layer extra tokens over a built-in base via `html[data-custom-theme]`. See `src/themes/theme-store.ts` and `design/themes.md`.
