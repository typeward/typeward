# Typeward — Claude Code project notes

Multiplatform editor app similar to Overleaf, format-agnostic: LaTeX and Typst, with live `.md` file preview. Targets desktop (Win/Mac/Linux) and tablets (iPadOS, Android tablets — no phones). Fully local: no account, no backend, no paid tier — every feature ships to every user, and third-party services (Zotero, WebDAV, GitHub, AI providers) are optional integrations the user wires up with their own credentials. Real-time collaboration is a future phase. (Jupyter `.ipynb`, Quarto, R Markdown, and Markdown-as-project are out of scope.)

**License: GPL-3.0-or-later**, declared in `package.json` and `src-tauri/Cargo.toml`. `LICENSE` is the verbatim GPLv3 text; `THIRD-PARTY-NOTICES.md` + `LICENSES/Apache-2.0.txt` cover the one component redistributed here, the vendored Apache-2.0 `harper-core` under `src-tauri/vendor/harper-core/`. Anything new that gets vendored needs a notices entry and its license text.

## Architecture seams — read before adding format-specific code

- **Integrations module** (`src/integrations/`, `src-tauri/src/integrations/`) — the substrate every third-party integration plugs into. Provider interfaces (`CitationProvider`, `CloudFsProvider`, `AiProvider`, `GrammarProvider`, `TemplateProvider`) live in `src/integrations/types.ts`. Each category has its own registry + init module that watches `integrationsSettings()` and registers providers reactively (`references/init.ts`, `cloud/init.ts`, `ai/init.ts`). `App.tsx` wires the inits at boot alongside `bootCoreCommands()`. Shared Rust primitives: `integrations::credentials` (OS keyring, service prefix `typeward.<provider>`, `credential_exists` for UI checks), `integrations::http` (`http_request` / `http_request_bytes` — allowlisted outbound funnel; `authRef` secrets are resolved from keyring inside Rust and bound to expected hosts), `integrations::oauth` (PKCE + `axum` loopback callback on `127.0.0.1:0`).
- **Local user profile** (`src-tauri/src/profile.rs`, `src/screens/settings/ProfileSection.tsx`) — who the user is *on this machine*; nothing about it is networked. Persisted settings section `profile` carries `displayName`, `email`, `affiliation`, plus a **backend-owned `avatarPath`**: only `set_profile_avatar` / `clear_profile_avatar` write it, `settings::merge_backend_owned` carries the on-disk value forward so a renderer `buildSettings()` roundtrip can't clear it, and the TS store mirrors it read-only (`noteProfileAvatar`, same pattern as `noteInstallId`). The picture is *copied* into `<app_data>/profile/avatar.<ext>` — extension allowlist (png/jpg/jpeg/webp/gif, lowercased), symlink + non-regular-file rejection, 8 MiB cap re-checked after the read, and exactly one stored file at a time — so it survives the user moving the original and no read scope has to widen to wherever the picker landed. `tauri.conf.json`'s `assetProtocol.scope` carries `$APPDATA/profile/**` so `convertFileSrc` can render it. The profile is a **fallback, never an override**: `CommitPanel` fills each git-author field only when `integrations.vcs.git.authorName`/`authorEmail` is blank, and `TemplateGallery` seeds a template's `author` variable default only when the manifest ships none.
- **`EditorAdapter`** (`src/adapters/<format>/`) — per-format glue: compile delegate + commands (`previewKind`/`cmExtensions` are optional/vestigial — kept for a test fake, not consumed. `languageId` is NOT: it is required and is what picks the LSP server for a newly-opened project, `asLspLanguage(adapter.languageId)` in `EditorScreen`. A wrong value silently disables LSP for that format, which no compile error would catch). Two concrete impls today: `LatexAdapter` (`compile_latex` → latexmk/pdflatex or Tectonic), `TypstAdapter` (`compile_typst` → native typst CLI). Each calls IPC through the leaf `src/commands/compile-runner.ts` (which breaks the old adapters↔actions import cycle). The format → adapter mapping is a **single source**: `adapterFor()` in `src/commands/actions.ts`, imported by `EditorScreen` (the former duplicate `adapterForFormat()` was removed 2026-07-02). Per-file/per-format dispatch tables live in `src/adapters/languages.ts` (extension→language, language→LSP/grammar) and `src/adapters/format-tables.ts` (prose facts, snippets); LaTeX-specific SyncTeX machinery lives in `src/adapters/latex/synctex.ts`. The aspirational `src/providers/` CompileProvider/PreviewProvider/LspProvider interfaces were deleted 2026-07-02 (`src/providers/compile/texlive-wasm-provider.ts` remains as the mobile engine).
- **Markdown files** — when the active editor tab is a `.md` file, the right pane swaps from `<PdfViewer>` to `<MarkdownPreview>` (markdown-it + local KaTeX renderer + DOMPurify; lives at `src/components/preview/MarkdownPreview.tsx`). Sandboxed HTML render with guarded relative-asset rewrite against the active file's directory; direct `file:` URLs, parent traversal, absolute paths, and unknown schemes are rejected. Debounced ~80ms. Does not participate in compile. See `docs/ntb_feature.md` for the removal rationale (its companion design spec was deleted with the superpowers tree — recover from git history if ever needed).
- **Visual editor (LaTeX, v3 — hidden-source WYSIWYG)** (`src/lib/visual/`; design/STATUS.md row AC) — Source | Visual mode for `.tex` files: one real document, the verbatim source; visual = a StateField of decorations + atomicRanges, and markup never renders in the page (source appears only in the edit popover). The full contract — total-coverage parse, no-inline-reveal, incremental-splice rules, borrowed text, chip labels, StyleNode-vs-chip severity, exhaustiveness guards — lives in `src/lib/visual/CLAUDE.md` (loads when working under that directory). Cross-module invariants outside that dir: mounted via compartment + dynamic import in `CodeMirror.tsx` (toggling preserves undo/LSP; NOT part of `editorKey`); mount/unmount dispatches ZERO doc changes (freeze test); vim force-suspends in visual; gutters/active-line off + wrap on are forced at the prop level in `text-shell.tsx`; `search.ts` rebinds Mod+F to a visible-image search; keep the `updateDoc ≡ full reparse` property test green when touching `parse/`.
- **`CommandRegistry`** (`src/commands/`) — wired through end-to-end. `bootCoreCommands()` runs at app startup; adapter commands register on project load (`EditorScreen`) and unregister on cleanup. The shared `<CommandPalette />` rendered at App root reads from `commands()` directly. Global shortcuts (`Mod+K`, `Mod+N`, `Mod+,`, `Mod+S`, format-specific compile) dispatch through `src/commands/keyboard.ts` — CodeMirror no longer hardcodes `Mod-s` / `Mod-Enter`. Save/compile orchestration lives in `src/commands/actions.ts` (single point that maps `project.format` → adapter). Editor-scoped commands gate on focus being inside `.cm-content` or `[data-editor-shell]`.
- **LSP transport** (`src/lib/lsp/client.ts` raw + `wrap()` JSON-RPC wrapper, `src/lib/lsp/cm6.ts` CM6 integration, `src/stores/lsp-store.ts`) — Rust owns child processes (`src-tauri/src/lsp.rs`); frontend talks over Tauri **event channels** (`emit`/`listen`), not `invoke` for streaming traffic. `invoke` is only used for `start_lsp` / `stop_lsp` / `send_lsp_message` lifecycle and outbound writes. **We hand-rolled the CM6 binding** rather than using `codemirror-languageserver` (that package is coupled to `@open-rpc/client-js` WebSocket transport).
- **Unified file watcher** (`src-tauri/src/watcher.rs`, `src/lib/watcher/client.ts`, `src/stores/watcher-store.ts`) — single `notify` service, frontend `fsVersion` signal bumps on each event, FileTree reads it as a resource key. `.typeward/` paths are filtered to avoid autosave feedback loops. Bursts coalesce on a 150ms quiet gap, **bounded by a 1s max window and a 512-event cap** so a process writing faster than the gap (external `latexmk -pvc`, a logger, a long download) can't starve emits while the event vector grows. **Rescan markers must survive**: inotify overflow / FSEvents `MustScanSubDirs` arrive with EMPTY paths, so the non-empty emit guard would drop them and leave the tree stale for the session — `need_rescan()` re-emits the project root instead, and backend errors are logged and converted into the same marker. The watcher **id is unique per start** (`watcher-store.ts`): Rust's map `insert` replaces, so a root-derived id let a stale `stop()` remove the live watcher after a fast away-and-back navigation.
- **Autosave** (`src/lib/autosave/index.ts`, `src-tauri/src/autosave.rs`) — debounced 500ms; snapshots to `<project>/.typeward/snapshots/<rel>.snap`; `RecoveryDialog` shows orphans on project open. The effect body is **async and re-entrant** — Solid does not await one run before starting the next — so it carries a run-generation guard (a run resuming after its awaited flush must not re-arm the timer over a newer one) and `isStale()`, which revalidates a captured `OpenFile` snapshot against the live store before writing. `isStale` is deliberately conservative: a closed tab or a torn-down project still flushes (losing the edit would be worse), and it only refuses when the buffer has moved on or the tab was *repointed* by a rename — writing the captured old path would otherwise resurrect the file the user just renamed away. `list_orphans`' walk is per-entry tolerant: one unreadable `.snap` must not abort the scan, since the caller treats an error as "no orphans" and the user would silently get no RecoveryDialog.
- **Telemetry** (`src/lib/telemetry/index.ts`, `src-tauri/src/telemetry.rs`) — Rust panic hook + frontend `error`/`unhandledrejection` → JSONL log at `<app_data>/telemetry.log` (capped 1000 entries, per-field caps). Local capture is always on, never networked by itself. Submission is a separate explicit surface (added 2026-07-07): **Settings → Diagnostics** (`src/screens/settings/DiagnosticsPanel.tsx`) lists recent events (kind badge, expandable detail, per-event Copy, "Export log" via `read_telemetry_log` + save dialog) and offers per-event **"Report this error"** — `preview_error_report` returns the exact scrubbed payload for a confirm dialog, `submit_error_report` sends it through the one-shot Rust Sentry client in `src-tauri/src/diagnostics.rs` (see Sentry bullet). The dialog works with `shareCrashReports` OFF on purpose: confirming it is the consent for that one event; the toggle governs only the automatic scan + frontend SDK. "Report a bug" (Diagnostics button + global `core.reportBug` palette command, `src/lib/bug-report.ts`) opens a prefilled GitHub new-issue URL — base in `src/config/feedback.ts`, allowlisted in capabilities; the target repo must be PUBLIC before shipping (plan 50 §2 stopgap) — with `collect_system_info` results (app version, OS/version/arch, active engine, tool probes as found/not-found booleans, never paths).
- **Sentry** (`src/lib/sentry.ts`, added 2026-07-06; opt-in gate added same day) — frontend crash/error reporting via `@sentry/browser` (NOT `@sentry/solid`: its `@solidjs/router` peer caps at ^0.15, we're on 0.16; the wrapper only adds a router integration + ErrorBoundary HOC we don't use). **Strict egress opt-in:** `installSentryGate()` (`src/lib/sentry-gate.ts`, called from App.tsx boot) watches the persisted `privacy.shareCrashReports` setting (default OFF; toggle in Settings → Security → Privacy) and dynamic-imports + inits the SDK only when enabled — opted-out users never fetch the chunk; toggling off calls `shutdownSentry()` (flush + disable). Don't reintroduce an unconditional boot kick, and keep all imports dynamic so the ~275 KB SDK chunk stays off the `check:bundle` boot path. **Crash/error events only (2026-07-13):** performance tracing and session replay were removed so the SDK sends exactly what the "Share crash reports" consent copy promises — don't reintroduce tracing/replay integrations without a separate, explicit consent surface. Ingest host is allowlisted in both CSPs (`connect-src https://*.ingest.de.sentry.io`); the `worker-src blob:` allowance predates Replay and stays for other workers. App-shell ErrorBoundary crashes are forwarded explicitly (`reportCrash`, gated on the same setting) since Solid-caught errors never hit `window.onerror`. Dev-only palette command `dev.sentryTest` ("Send Sentry test error") verifies the end-to-end pipeline (toasts a hint when the opt-in is off). Local telemetry.log capture is unchanged, always on, and remains the pre-init safety net. **Rust-side submission (2026-07-07):** `src-tauri/src/diagnostics.rs` duplicates the same public DSN (cross-referenced comment) and uses the official `sentry` crate as a ONE-SHOT client — init with `default_integrations(false)`, no session tracking, capture, flush with timeout, drop the guard; sends serialize behind a lock because `sentry::init` swaps global hub state. The crate is at **0.48.5 with only the `reqwest` feature, deliberately NOT `rustls`** (2026-07-30): sentry's `rustls` feature selects rustls-with-aws-lc-rs, which drags in aws-lc-sys → cmake/NASM (a real build hazard, worst on Windows CI). The `reqwest` feature alone gives sentry its own reqwest 0.13 transport on ring-based rustls-tls (no aws-lc, no native-tls, no new openssl) — matching the app's ring TLS stack. Don't re-add `rustls` here or the aws-lc hazard returns. Scrubbing is a pure, unit-tested Rust fn applied before send: home dir → `~` (both slash styles, ASCII-case-insensitive), remaining absolute paths (drive/UNC/POSIX) → basename, URLs/`~/...`/relative paths untouched; no file attachments, `send_default_pii=false`, no `server_name`. Identity = `privacy.installId`, a random UUIDv4 minted by Rust on FIRST submission only; the TS settings store mirrors it read-only (`noteInstallId`) so `buildSettings()` roundtrips can't clobber it. **Crash-on-previous-run scan:** `scan_and_submit_crashes` (kicked once per session from `sentry-gate.ts` when the opt-in is on; Rust re-checks the setting and guards once-per-process) submits `panic` events newer than the RFC3339 watermark file `<app_data>/telemetry.submitted`, at most 5 per launch, oldest first; the watermark advances only after a successful flush so undelivered panics retry next launch. **Source maps:** `@sentry/vite-plugin` in vite.config.ts, **opt-in via `SENTRY_UPLOAD=true`** — an ordinary `npm run build` is hermetic and never contacts sentry.io even on a machine that has a token configured (release.yml sets `SENTRY_UPLOAD=true` + `SENTRY_AUTH_TOKEN` on the release build; that is the only path that uploads). Only when opted in is `SENTRY_AUTH_TOKEN` read from `.env.sentry-build-plugin` (gitignored; see .env.example). It emits `hidden` sourcemaps, symbolication matches via injected Debug IDs (release auto-named from the git SHA), and maps are deleted from dist/ after upload because `tauri build` ships dist/ verbatim (a leftover .map = full source leak). No opt-in or no token → no maps generated at all. Upload failures warn but don't fail the build — watch for `[sentry-vite-plugin] Error` lines. Verified compatible with Rolldown-Vite (Vite 8).
- **Responsive layout** (`src/stores/viewport-store.ts`, `src/components/layout/PaneSwitcher.tsx`, `src/lib/gestures.ts`) — `viewportMode()` flips at the 1024px breakpoint. `TextShell` keeps a desktop `DesktopLayout` (corvu Resizable, unchanged) and a tablet variant that swaps in `<Switch>`-based single-pane rendering, the `PaneSwitcher` segmented control, the slide-up `LogsSheet`, and a swipe listener. `setActivePane()` is the public lever for pane navigation; treat `cyclePane()` as gesture-only. Don't add fixed-width assumptions in shells — guard behind `isTabletViewport()` instead.
- **texlive-wasm CompileProvider** (`src/providers/compile/texlive-wasm-provider.ts` + `texlive-wasm-assets.ts`) — mobile-only Web Worker LaTeX engine via **`@typeward/texlive-wasm`, an ordinary npm dependency pinned at `0.2.4-alpha`** (Typeward's MIT-licensed sibling project, published rather than linked since 2026-08-05 — a plain `npm install` from a bare clone is all it takes). Selected when `compileEngine() === "texlive-wasm"`; not available on desktop. Note the split between package name and engine name: only the **module specifier** is scoped. The engine *identifier* `"texlive-wasm"` — the `CompileEngine` union member, the `public/texlive-wasm/` and `src-tauri/resources/texlive-wasm/` asset directories, the `$RESOURCE/texlive-wasm/**` capability globs — is deliberately unscoped and must stay that way. `LatexAdapter.compile()` dynamic-imports the provider so the WASM bridge isn't pulled into desktop bundles when unused. **Assets live in two places on purpose** (`texlive-wasm-assets.ts` is the single source for both): the **engines** (glue `.js` + `.wasm`, one artifact per engine) go under `public/texlive-wasm/<engine>/emscripten/` because the engine worker `import()`s the glue and `fetch()`es the wasm *by URL* — only the app's own origin satisfies the CSP (`script-src 'self'`), and Vite copies `public/` verbatim into `dist/`, which `tauri build` ships as the webview root. The **TeX Live tree** goes under `src-tauri/resources/texlive-wasm/texmf/` and is read lazily off disk through TauriFS (`BaseDirectory.Resource`, capability-scoped) — far too large for the bundle graph. **It is bundled on MOBILE ONLY** (2026-07-13): `bundle.resources` in `tauri.conf.json` lists only `resources/templates/**/*`, and the `resources/texlive-wasm/**/*` glob is added back by the `tauri.android.conf.json` / `tauri.ios.conf.json` platform overlays (the same mechanism that already zeroes `externalBin` — the Tectonic sidecar is desktop-only). Tauri merges those overlays with **RFC 7386 JSON Merge Patch, where arrays REPLACE rather than append**, so each overlay must restate the full `resources` list — dropping `templates` from it would silently un-bundle the built-in templates on mobile. Keep the tree out of the desktop config: a developer who runs `npx texlive-wasm download-assets` and then `tauri build` would otherwise ship a multi-hundred-MB TeX Live tree inside a DESKTOP installer, where the wasm provider (hard-gated behind `isTauriMobile()`) can never reach it. Every engine gets an explicit `enginePath` (`createEngine` for pdflatex; a `latexmk` `engineConfig` factory for the bibtexu/biber/makeindex helpers, all sharing the one TauriFS backend) — without it the worker throws `config.enginePath is required` at init. The availability probe checks glue + wasm + a non-empty TDS and returns an actionable unavailable-state (`texliveWasmUnavailableReason()`); a document that needs a helper engine whose artifact wasn't downloaded is refused with a named diagnostic instead of failing inside the worker. Compilation goes through `latexmk()`. PDF bytes are persisted via the project-scoped `write_project_binary_file` IPC into `<project>/.typeward/build/<base>.pdf` so the existing file-path-driven PdfViewer renders it unchanged. Diagnostics route through the shared Rust parser via the `parse_latex_log_cmd` IPC. The provider walks both text dependencies (`.tex`, `.bib`, `.cls`, `.sty`, etc., read via `read_project_text_file`) and binary figures (`.png`, `.jpg`, `.jpeg`, `.pdf`, `.gif`, `.eps`, via `read_project_binary_file`); capped at 200 files / 10 MB combined.
- **Reference aggregator** (`src/integrations/references/aggregator.ts`) — `refreshLibraryBib(project)` calls `exportAllAsBibTex()` on every registered `CitationProvider` (Zotero local — Better BibTeX or Zotero 7's built-in API, Zotero Web, Mendeley), pulls in `<project>/.typeward/citations/local.bib` (DOI/arXiv lookups land here), dedupes by citation key, and writes the unified result to `<project>/.typeward/citations/library.bib`. The texlive-wasm walker auto-discovers it; texlab/tinymist see it as a normal `.bib` and provide `\cite{}` completions for free. Per-provider config lives in `IntegrationsSettings.references.{betterBibTex,zoteroWeb,mendeley}`; tokens live in the keyring under service names matching the provider id. (JabRef `.bib`-file import was removed 2026-06-13 — point Zotero at the library instead, or DOI-lookup into the project `local.bib`.)
- **Cloud sync engine** (`src/integrations/cloud/core/engine.ts`) — generic bidirectional orchestration; one `SyncEngine` per active cloud-backed project; the local cache under `<projectsRoot>/.remote-cache/…` IS a normal Typeward project. **WebDAV (`cloud/webdav/`) is the only cloud backend** — Nextcloud, ownCloud, any WebDAV host; `CloudProviderId` is the single-member union `"webdav"`. Dropbox was removed 2026-08-05 (provider, OAuth flow, `VITE_DROPBOX_CLIENT_ID`, the `*.dropboxapi.com` outbound-allowlist and `www.dropbox.com` OAuth/opener entries) — WebDAV needs no registered app and no client id, which is the point. The engine, conflict resolution and the `.remote-cache` layer stayed generic and untouched; adding a second provider means implementing `CloudFsProvider` and widening that union, not reworking the engine. A project whose `.typeward/project.json` still carries `cloudOrigin.provider === "dropbox"` reads as **not cloud-backed** (`readCloudOrigin` in `cloud/registry.ts` returns null): it opens, edits and compiles as a plain local folder, nothing on disk is rewritten, and no sync chip renders. Don't add a migration that mutates those files. Saves feed `engine.queuePush()` via `notifyLocalSave` (`cloud/init.ts`); pull and push serialize through one promise chain; `.typeward/` never syncs and remote rel paths are funneled through `normalizeRemoteRelPath`. The full contract — pull/push failure semantics, pendingRetries salvage, echo suppression, conflict detection/resolution, remote seeding, engine lifecycle — lives in `src/integrations/cloud/CLAUDE.md` (loads when working under that directory).
- **AI streaming primitive** (`src-tauri/src/integrations/ai/streaming.rs`, `src/integrations/ai/stream.ts`) — one Rust task per stream, format-specific parsers in `parse_event()` (AnthropicSse / OpenAiSse / GeminiSse / OllamaNdjson). Chunks emit on a per-stream Tauri event channel `ai-stream:<streamId>`; stream ids are restricted to short ASCII `A-Z a-z 0-9 _ -` values and duplicate ids are rejected so abort handles cannot be orphaned. The frontend `aiStream(req, signal)` AsyncIterable adapter listens, yields each delta, calls `ai_stream_abort` when the AbortSignal fires. Stream URLs pass the same outbound allowlist as `http_request`; OpenAI/Anthropic/Gemini keys use `authRef` and stay in Rust. Error bodies and unterminated stream buffers are capped to avoid unbounded memory growth from attacker-controlled endpoints. All four providers (Claude/ChatGPT/Gemini/Ollama) implement the same `AiProvider` shape (`models()` + `chat(messages, opts)`); only one is active at a time per `IntegrationsSettings.ai.activeProvider`. The master switch `integrations.ai.enabled` **defaults OFF** on both the TS and Rust sides — every provider needs an API key or a local daemon the user sets up first, so no AI surface renders and zero AI traffic leaves the app until it's turned on. Don't flip that default.
- **Local git** (`src-tauri/src/integrations/vcs/git.rs`) — libgit2 via the `git2` crate, every operation wrapped in `tokio::task::spawn_blocking` because libgit2 is fully synchronous. HTTPS auth comes from the keyring under service `git.<host>` so a single GitHub device-flow sign-in covers both REST API calls (via `httpRequest` `authRef`) and libgit2's push/pull callbacks. SSH transport is out of scope; only HTTPS + PAT, and git IPC now rejects non-HTTPS remotes (`file://`, SSH URLs, scp-style remotes). `git_pull` is fast-forward only and refuses to checkout when the worktree has staged, unstaged, or untracked changes — merge commits still need a conflict UX we don't ship yet.
- **Harper grammar** (`src-tauri/src/integrations/grammar/mod.rs`, `src/lib/grammar/cm6.ts`) — Rust-native, runs in-process via `harper-core`. `grammar_check(text, file, syntax)` IPC returns diagnostics in the same shape as compile/LSP diagnostics so the existing gutter renders them without changes. CM6 linter extension via `@codemirror/lint`, debounced 400ms; up to 3 quick-fix actions per lint. Wired into the editor only when `integrations.grammar.enabled` (defaults OFF) — zero IPC when off. `harper-core` is `[patch]`ed to the vendored copy at `src-tauri/vendor/harper-core/` (upstream 2.7.0 doesn't compile on recent rustc); it is the one redistributed third-party component, so keep its Apache-2.0 text and `THIRD-PARTY-NOTICES.md` entry in sync when bumping.
- **Templates** (`src-tauri/src/integrations/templates.rs`) — `templates_list()` merges built-ins from `<resource>/templates/` (bundled per `tauri.conf.json` `bundle.resources`) with user customs at `<app_data>/templates/custom/`. Each template ships a `template.json` manifest plus its files; `template.files[*].template = true` opts a file into Handlebars-subset `{{var}}` substitution at `template_instantiate` time. Other files copy verbatim. IDs are namespaced (`builtin:<id>` / `custom:<id>`) so short names don't collide across sources. `template_save(project, name, description)` does the reverse — captures the open project into `<app_data>/templates/custom/<id>/` (skips `.typeward/`/`.git/`/symlinks/LaTeX build junk, copies the rest verbatim, writes a `template.json` with empty `variables`/`files`). Triggered by the `core.saveTemplate` command → `<SaveTemplateDialog>` mounted at the App root via the `requestSaveTemplate` signal.

## Gotchas

- **`src/widgets/` is intentionally unmounted, not dead code.** The registry + DashboardPanel + builtins were removed from `ProjectsScreen` on 2026-07-01; the code and the `dashboard*` settings are kept for its return (see `design/widgets.md`). Don't delete them as unreferenced.
- **"Open with Typeward" is a handshake, not an emit** (`lib.rs::open_with`, `src/lib/open-with.ts`, 2026-08-05). A cold launch hands Rust the path before the webview exists — always on a Finder/Explorer double-click, and on macOS that Apple Event is the *only* route (Finder opens never reach argv). Tauri events are fire-and-forget to current listeners, so emitting straight away silently lost the open. Rust parks the path; the frontend drains it with `take_pending_open` as its listener mounts, which also marks the frontend ready so later opens (the single-instance case) emit directly. The old 1500ms deferred emit is gone — don't reintroduce a sleep-and-hope.
- **`settings::validate_projects_root` needs an anchor, and mobile has none.** `dirs::document_dir()` is `None` on Android/iOS *and* on Linux without `xdg-user-dirs`. Since `save_locked` validates on every write, a `None` anchor meant **no setting could ever persist** on mobile, and `default_projects_root` degraded to a RELATIVE `"Typeward"` (cwd-dependent library on Linux, unusable trust root on mobile). `root_anchor()` resolves Documents → the mobile-seeded app-data anchor (`settings::set_root_anchor`, called from `lib.rs` setup BEFORE the first load) → `~/Documents`. Keep the seeding before the first `settings::load`, since load sanitizes against the same anchor.
- **Sync Tauri commands run outside the tokio runtime.** Calling `tokio::spawn` from a sync `#[tauri::command]` panics with "no reactor running" and aborts the process (Windows reports `STATUS_STACK_BUFFER_OVERRUN` / `0xc0000409`). Mark any command that touches tokio (`spawn`, `mpsc`, `tokio::process`, etc.) as `pub async fn`. Reference: `watcher.rs::watch_project`.
- **Tauri 2 fs plugin scope = static capability entries UNION the runtime scope.** `fs:default` + bare `fs:allow-*` permissions don't grant access to arbitrary paths — they need an `allow` list, and the plugin checks `capability_scope.is_allowed(path) || runtime_scope.is_allowed(path)` (a runtime *forbid* still wins over both). Since 2026-07-13 the static entries in `capabilities/default.json` cover only the DEFAULT projects root (`$DOCUMENT/Typeward/**`) plus `$RESOURCE/texlive-wasm/**` — **not `$DOCUMENT/**`** — and `lib.rs::grant_projects_root_fs_scope` adds the *configured* projects root to the runtime scope at startup and again from `save_settings` when the user moves it. Save/open destinations outside the projects root keep working because `tauri-plugin-dialog` adds every user-picked path to that same runtime scope. The runtime scope is app-global (not per-window), so it is also the floor the `preview` capability cannot go below. Custom project IPC (`read_project_text_file` / `write_project_text_file` / `write_project_binary_file`) still validates canonical project-relative paths. **`fs:allow-read-file` (binary) is separate from `fs:allow-read-text-file`** — PDF reads need the binary one. Don't reintroduce a Documents-wide static grant; widen the runtime scope instead, and only for a path the user chose.
- **PDF.js `RenderingCancelledException`** is benign — fired whenever a render is superseded by a newer one (e.g., on quick recompile). `PdfViewer` uses a generation counter and silently swallows it. Don't surface it as an error.
- **Custom Tauri commands bypass fs plugin scope** — project file IO must use `read_project_text_file` / `write_project_text_file` / `write_project_binary_file`, which validate project-relative paths against the canonical root. Compile commands also validate `project.rootFile`. Don't reintroduce raw absolute-path file IPC.
- **CodeMirror remount on tab switch** — `text-shell.tsx` keys CodeMirror on `activeFile().path` so the LSP gets a fresh `didOpen` per file. Don't try to swap content in place via dispatch; that breaks LSP doc tracking.
- **`@fontsource-variable/inter` + `@fontsource-variable/jetbrains-mono`** ship variable fonts (one axis file per family, plus an italic axis file). `App.tsx` imports the Inter + JetBrains Mono index and wght-italic CSS. They block initial paint in dev — biggest contributor to the pre-paint flash before `backgroundColor` in `tauri.conf.json` made the window paint in the default theme's bg on creation (`#F8F4EA` since the Daylight default; was `#0A0B0F` in the Aurora era). The boot splash in `index.html` defaults to Daylight colors and `public/boot-theme.js` (a classic script served verbatim from public/ — kept out of the Vite bundle graph so the re-tint runs before the app bundle even in release builds; external because CSP forbids inline scripts) re-tints it from the persisted theme, so dark-theme users don't get a cream flash. A previous `visible: false` + `getCurrentWindow().show()` deferred-reveal pattern was removed: it masked render-time crashes (window stayed hidden if `onMount` never fired), and the static background alone is sufficient.
- **Compile fallback chain**: `system-tex` engine tries `latexmk` first, falls back to `pdflatex` on spawn/exit failure (MiKTeX sometimes ships latexmk without a usable Perl). `tectonic` engine tries the sidecar (`binaries/tectonic-<triple>`) first, falls back to `tectonic` on PATH. Either way, the actual command + log get surfaced in the LogsDrawer's Logs tab. **All compile subprocesses are bounded (2026-07-13):** `run_bounded` in `compile.rs` enforces a 10-minute timeout and a head+tail-capped output capture (4 MiB head + 256 KiB rolling tail, so TeX's trailing `! ...` fatal lines survive truncation), and kills the whole process tree on deadline (taskkill `/T` on Windows, `setsid` + group SIGKILL on Unix). A timeout does NOT trigger the latexmk→pdflatex or sidecar→PATH fallbacks (that would double the wait) — it surfaces as a parser-visible timeout line in the log. Route new compile spawns through `run_bounded`, not raw `Command::output()`.
- **Typst syntax highlighter is hand-rolled.** `src/adapters/typst/typst-language.ts` is a minimal CM6 `StreamLanguage` covering the visual basics (comments, strings, math, `#funcs`, headings, emphasis). It's intentionally not a full grammar — when tinymist's structured tokens become consumable through the LSP transport, prefer those over expanding this parser.
- **SyncTeX shells out to the system `synctex` CLI** (`src-tauri/src/synctex.rs`), not a Rust binding. TeX Live / MiKTeX / MacTeX all ship it; the CLI returns `Ok(None)` if not on PATH so Tectonic-only users get a graceful "no sync" rather than an error. Compile flags: `-synctex=1` for latexmk/pdflatex, `--synctex` for tectonic. Forward search wires through `requestPdfScroll(page, y)` → PdfViewer's `scrollTarget` effect. Inverse search is **double-click** on a PDF page (shift+click still works as a secondary path) → `triggerInverseSearch` → `onPageClick(page, x, y)` (coords divided by current zoom to get PDF pts) → `requestGotoSource(relPath, line)` → EditorScreen opens the file and moves the cursor via the imperative `editor-view-store` handle.
- **Linux dev hosts need `libdbus-1-dev`** for the `keyring` crate's Secret Service backend, plus `libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev` for Tauri's GTK chain. Apt one-liner: `sudo apt install -y libdbus-1-dev libwebkit2gtk-4.1-dev build-essential libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.
- **Tectonic sidecar naming** — `fetch-tectonic.mjs` downloads the musl static binary (`tectonic-x86_64-unknown-linux-musl`), but Tauri's build script looks up the rustc target triple (`tectonic-x86_64-unknown-linux-gnu` on Linux). Symlink `gnu → musl` after fetch if Tauri build complains: `ln -sf tectonic-x86_64-unknown-linux-musl tectonic-x86_64-unknown-linux-gnu` in `src-tauri/binaries/`. The musl binary works fine on glibc systems — it's statically linked. **Windows on ARM (`aarch64-pc-windows-msvc`) has no upstream Tectonic build** — Tectonic ships only x86_64 Windows assets — so `tauri build`/`tauri dev` would otherwise fail resolving the `externalBin` sidecar. The `win32:arm64` entry in `fetch-tectonic.mjs` deliberately downloads the x86_64 archive and installs it under the aarch64 triple name; Windows 11's x64 emulation runs it (verified `--version`). It's the same archive+digests as `win32:x64`. There is no Windows/arm64 leg in `build.yml`/`release.yml`, so this only unblocks local ARM64 dev builds; the runtime already falls back sidecar → PATH `tectonic` → error regardless.
- **OAuth client ids come from `.env`** as `VITE_<provider>_CLIENT_ID`; Mendeley and GitHub each need their own registered app. The code paths are valid without the env vars — sign-in just throws an actionable "register your app at <url>" error. **Two different flows, and only one of them is `runOauthFlow`.** GitHub uses its own **device flow** (`src/integrations/vcs/github/auth.ts`: poll `github.com/login/device/code`, no redirect, no loopback server, no `oauth_begin`). **Mendeley is the only `runOauthFlow` / `oauth_begin` caller left** — since the Dropbox provider was removed (2026-08-05) no PKCE *public* client is wired up at all, though the PKCE machinery in `integrations::oauth` is intact and is what a future public client would use. Mendeley is a *confidential* client: it doesn't support PKCE and exact-matches the redirect URI with no dynamic ports. So its flow (`runOauthFlow({ clientSecret, redirectUri })` → `oauth_begin`) passes a `client_secret` (stored in the keyring under service `mendeley` account `app-secret`, entered in Settings; the token exchange uses HTTP Basic via reqwest `.basic_auth`, and the frontend refresh attaches `Authorization: Basic` via the `api.mendeley.com` raw-auth-header allowance) and a full `redirect_uri` the user pastes from their Mendeley registration (default `http://localhost:5000/callback`, persisted in `references.mendeley.redirectUri`). `oauth_begin`'s `redirect_uri` override is loopback-validated (`parse_loopback_redirect`: http + `localhost`/`127.0.0.1`/`::1` + explicit port) and binds **both** IPv4 and IPv6 loopback on that port so `localhost` resolves either way; a busy port returns an actionable error. A caller that omits `redirect_uri` still gets the random `127.0.0.1` port. Loopback servers are shut down via a `broadcast` channel (multiple listeners).
- **`http_request` returns text body; binary needs `http_request_bytes`** — the text variant truncates non-UTF-8 payloads, so anything moving raw bytes over the allowlisted funnel must use the binary IPC and its `httpRequestBytes` wrapper (`src/integrations/http.ts`). Both commands enforce an outbound host/scheme allowlist; `authRef` credentials are bound to expected provider hosts and raw auth headers are rejected for metadata-only hosts. **As of 2026-08-05 `httpRequestBytes` has zero callers in `src/`** — Dropbox was its only consumer and WebDAV moves bytes over its own `webdav_get` / `webdav_put` SSRF-screened client. Both halves were kept deliberately: it is a live, tested primitive with no current consumer, and it is the right thing to reach for the next time a provider needs binary IO. If it is ever removed, remove the Rust command and the TS wrapper **in the same change** — `src/ipc/drift.test.ts` fails on a command registered on one side of the bridge only.
- **The frontend cannot read keyring secrets at all — there is no read command.** `credentials.rs` exposes exactly three IPCs: `credential_set`, `credential_exists`, `credential_delete`. `get_secret` is an internal Rust fn; API keys, OAuth tokens, and the WebDAV password are resolved from the keyring *inside* Rust via `authRef` (bound to expected hosts) and never cross the bridge. `credential_exists` is the only probe UI state may use. Don't add a generic read back.
- **`git_pull` is fast-forward only and requires a clean worktree.** Merge commits surface as an error verbatim — the user resolves by hand for now. The conflict surface that would handle non-fast-forward pulls is the same gap that keeps SSH transport out of scope.
- **OS keyring on Linux blocks on D-Bus.** All `credential_*` IPC handlers spawn-blocking around the sync keyring API so the Tokio runtime (LSP / watcher / autosave / cloud sync) doesn't park during a Secret Service unlock prompt. New keyring callers should follow the same `tokio::task::spawn_blocking` pattern.
- **Keyring records must stay short.** Windows Credential Manager caps a blob at 2560 bytes (≈1280 chars after UTF-16 encoding) and silently fails to persist anything larger. Every secret we store is a single API key or OAuth token that Rust reads back via `authRef` — keep it that way; there is no chunking layer to fall back on. Use `describeIpcError` from `src/lib/errors.ts` (the single canonical normalizer; `toast.ts`'s deprecated `errorText`, re-exported by `Toaster`, aliases it) instead of `String(e)` when surfacing IPC errors — never `[object Object]`. Rust commands reject with a plain Display string (see the error-contract invariant), so a string rejection is the message verbatim.
- **CodeMirror's `defaultKeymap` binds `Mod-Enter` to `insertBlankLine`.** We filter it out in `CodeMirror.tsx` (`defaultKeymap.filter((b) => b.key !== "Mod-Enter")`) because the global keyboard router also dispatches Mod+Enter as compile — without the filter every compile shortcut also injected a blank line into the doc. Any new keymap source must not reintroduce a `Mod-Enter` binding.
- **Persisted settings enums are validated at the load boundary.** `settings-store.ts` runs every enum-shaped field (theme, accent, density, view, sort) through `validEnum(raw, allowed, fallback)` when reading `settings.json`, so stale values from removed variants (e.g. the deleted `obsidian`/`graphite` themes) degrade to defaults instead of rendering an unthemed app. Register any new persisted enum there.
- **Zotero integration has two local paths.** The provider probes Better BibTeX first, then falls back to Zotero 7's built-in local API — BBT is optional; don't make BBT-specific endpoints a hard requirement. Everything else — auto-discovered libraries (no library-id setting), the two-selector References panel design, node-id grammar, per-node caching/TTL rules, trashed-collection pruning, Mendeley API gotchas (marker-only pagination; no folder filter on /documents), and citekey consistency with `library.bib` — lives in `src/integrations/references/CLAUDE.md` (loads when working under that directory).

## Security invariants (established 2026-06-10 audit)

Threat model: local user is trusted; adversaries are malicious project content (cloned repos, Overleaf zips, custom templates, `.md`/`.tex`/`.bib`/log files) and attacker-controlled remote content (cloud-synced files, Zotero/Mendeley records, git remotes, AI endpoints). Webview XSS = arbitrary IPC = file write + process spawn, so the `.md` preview and any future HTML sink are critical surfaces.

- **Project-relative paths reject leading-dash components.** `validate_project_relative_path` (`project.rs`) rejects any path component starting with `-`. `project.rootFile` flows into latexmk/pdflatex/tectonic/typst as a positional argument; a file named `-shell-escape` or `-output-directory=…` would otherwise be parsed as a flag (argument injection → RCE-adjacent). Keep this guard; don't bypass it with raw absolute-path IPC.
- **Project metadata is validated on write, not only on read.** `project::write_project` validates `rootFile` with `validate_project_relative_path()` before persisting `.typeward/project.json`, so imports/templates cannot return an unsafe in-memory `Project` that only fails later on reopen or compile.
- **Renderer-supplied project roots are gated to opened projects.** Custom file IPC validates paths relative to whatever root the webview supplies, which alone would let XSS read/write/compile anywhere (e.g. `~/.ssh`). `project.rs` keeps a registry of roots the user actually opened — `register_root` is called ONLY from the `open_project`/`list_projects`/`create_project`/`import_project_folder` paths after those paths prove the root is either already registered or under the configured projects root — and `read/write_project_*`, `set_project_integrations`, compile, snapshots, synctex, and `watch_project` all gate on `is_registered_root`. The configured `projectsRoot` is validated under Documents at the settings boundary; brand-new clone/init destinations require `is_new_path_under_projects_root`. Existing-repo git ops require a registered root. Don't add a project-root IPC without one of these gates.
- **Subprocesses spawn `which`-resolved absolute paths, never bare names.** `Command::new("latexmk"/"pdflatex"/"tectonic"/"typst"/"texlab"/"tinymist"/"synctex")` + `current_dir(project)` let Windows' `CreateProcess` resolve the program against the *project* directory first, so a planted `typst.exe` in a malicious project would run (binary planting → RCE). Compile (`compile.rs`), LSP (`lsp.rs`), and SyncTeX (`synctex.rs`) resolve through the single `detect::resolve_program(name)` helper (which runs with the app CWD, not the project) and spawn the returned absolute path. The Tectonic sidecar is already safe (Tauri hands it the bundled absolute path). Keep this; route new spawns through `detect::resolve_program` — don't reintroduce bare-name spawns or scattered `which::which` calls. **Every self-built `Command` must also go through `detect::hide_console` (std) / `hide_console_async` (tokio)** (added 2026-08-05): release builds are `windows_subsystem = "windows"`, so Windows allocates a *fresh visible console* for each console-subsystem child without `CREATE_NO_WINDOW` — a black window for the whole latexmk run on every compile, one parked on the taskbar for the life of a texlab session, plus taskkill and `--version` probe flashes. Piped stdio does not suppress it, and `tauri dev` never reproduces it (debug builds keep a console the children inherit). `tauri-plugin-shell` sets the flag itself, which is why the bundled sidecar was always silent.
- **Project writes must not follow symlinks.** `write_project_binary_file` rejects a symlink leaf before writing (`resolve_project_write_path` only canonicalizes the parent). Text writes use `fs_ops::atomic_write`, which creates unpredictable temp files with `create_new` before rename so a malicious project cannot pre-plant `.name.tmp` as a symlink and redirect the write outside the project.
- **The outbound allowlist is enforced on every redirect hop, not just the initial URL.** `http::allowlist_redirect_policy()` re-validates scheme+host on each 3xx and is wired into the shared `http.rs` client AND the per-stream AI client (`ai/streaming.rs`). Build outbound clients through the single `http::outbound_client_builder()` constructor (2026-07-02), which always installs this policy; a new hand-rolled `reqwest::Client` reaching third parties must install the policy (or `Policy::none()`) itself — the default follows up to 10 redirects and would turn an allowlisted open-redirect into an SSRF primitive. (WebDAV keeps its own dedicated SSRF-screened client, which also installs the policy.)
- **IPC error contract: commands reject with a plain Display string, not a serialized enum.** Every `#[tauri::command]` maps its typed error to `String` at the boundary (`.map_err(|e| e.to_string())`); internal fns keep their `thiserror` types. This preserves the authored message across the bridge (a serialized enum object surfaced as `[object Object]`). The frontend's single normalizer is `describeIpcError` in `src/lib/errors.ts` (treats a string rejection as the message; unwraps `Error`/`{message}`/`{error}`; never returns `[object Object]`). `recordError` is bulletproof (a synchronous throw from the IPC layer can't break the caller). Never put secrets/tokens/response bodies in error strings.
- **Git and the `.typeward` sidecar compose via `.git/info/exclude`.** `project::ensure_sidecar_git_excluded(root)` writes `.typeward/` into `.git/info/exclude` (never the user's `.gitignore`) on init/clone/open/import; `git.rs::is_sidecar_path()` additionally filters `.typeward` out of `git_status`, `ensure_clean_worktree` (so pulls aren't permanently DirtyWorktree-blocked), and the `git_stage` add-all default (so snapshots/build/reviews are never committed). Mirrors the cloud engine's `normalizeRemoteRelPath` guard. Keep both layers.
- **Remote relative paths are a branded type.** `normalizeRemoteRelPath` (`cloud/core/paths.ts`) returns an opaque `NormalizedRelPath` that the cache-IO functions require, so a raw string can't reach cache IO without passing the funnel (the `.typeward`/traversal/absolute/drive rejections). Don't cast around the brand.
- **WebDAV uses a dedicated, account-gated, SSRF-screened outbound client — NOT the shared `http_request` allowlist.** A WebDAV server is a user-supplied host, so `integrations/webdav.rs` builds its own per-request `reqwest` client: it resolves the host, screens every resolved IP against a deny-table (loopback / link-local / cloud-metadata `169.254.169.254`+`fd00:ec2::254` / `0.0.0.0` blocked unconditionally; RFC1918 / ULA / CGNAT blocked unless the account opted into a private/LAN host), pins the connection to the vetted IP (resolve-then-pin, anti-rebinding), ALSO screens numeric-literal hosts (decimal/hex/octal/IPv4-mapped — a literal host bypasses the resolver, the Vaultwarden bug class), and follows only same-host https redirects. A host is accepted only if it matches a persisted, user-confirmed WebDAV account (allowlist-by-account — same shape as renderer-roots-gated-to-opened-projects). PROPFIND multistatus XML (attacker-controlled) is parsed in Rust with `quick-xml` (non-validating → immune to XXE and entity-expansion), never the webview DOMParser. The Basic-auth password lives in keyring service `webdav`; username + base URL live in `cloud.accounts`. Don't route WebDAV through the fixed-allowlist funnel or relax `allowed_https_host` for user hosts. **Two additions from the 2026-08-05 review:** (1) `request_url` — the single chokepoint for get/put/delete/propfind/ensure_ancestors — rejects `.`, `..` and `.typeward` segments (`reject_escaping_rel`). `SEGMENT` leaves `.` unencoded (it is RFC 3986 unreserved), so a `..` survived percent-encoding and `Url::join` resolved it, climbing above the enrolled base collection while staying on the vetted host. (2) `webdav_enroll_probe` is the ONE command that does not resolve its account from settings, because the first connection to a server cannot already be in settings — it validates https + the per-request SSRF screen exactly like the rest, persists nothing, and **recomputes the account id from the supplied host + username and requires a match**, so it cannot be used to aim an already-enrolled account's stored password at another host. Keep that binding if you touch it.
- **OAuth endpoints are provider allowlisted.** `oauth_begin` validates both authorization and token endpoints against a hardcoded host+path table before opening the browser or exchanging a code — since the Dropbox removal that table is exactly `api.mendeley.com/oauth/authorize` and `api.mendeley.com/oauth/token`, so a new provider needs an entry there, not a relaxation; extra auth params cannot override PKCE core fields (`redirect_uri`, `state`, `code_challenge`, etc.). The optional confidential-client `redirect_uri` override is loopback-only (`parse_loopback_redirect` rejects non-loopback hosts, non-http, and missing ports) so the renderer can't redirect the auth code to an external host. Token POST redirects stay disabled and successful token bodies are capped before parsing. Token-bearing response bodies — and the client secret — are never echoed into error strings (they would leak into `telemetry.log`).
- **Cloud `.typeward` guard is case-insensitive at any path depth.** `normalizeRemoteRelPath` (`cloud/core/paths.ts`) rejects any segment equal to `.typeward` case-insensitively — on Windows/macOS a remote file named `.Typeward/...` would otherwise overwrite snapshots / the sync cursor / the id↔path map.
- **Zip/template import limits.** Overleaf zip extraction caps entries (5k) and total uncompressed bytes (500 MB) as a decompression-bomb guard; zip entries reject symlinks, internal `.typeward`/`.git` paths, parent traversal, absolute paths, and leading-dash components. `template_id` is rejected if it contains path separators or `..` before being joined onto the templates root; template manifests and file paths reuse project-relative validation, skip internal dirs, and refuse symlink-backed source files.
- **IPC readers and subprocess bridges are bounded.** LSP `Content-Length` frames are capped before allocation, project text/binary reads have IPC size caps, source-bundle export streams files into the zip instead of buffering whole files, SyncTeX IPC validates source/PDF paths under the active project root, autosave recovery skips symlinked snapshots, and AI streams cap error bodies plus unterminated event buffers.
- **Telemetry fields are length-capped** (`summary` 2k, `detail` 16k chars, truncated on a char boundary) so a frontend loop can't amplify the JSONL log.
- **texlive-wasm walker includes `.typeward`** (only `.git`/`node_modules`/`build`/`out`/`dist` are pruned) so `.typeward/citations/library.bib` resolves on mobile — this is the documented aggregator invariant.
- **Privileged IPC is main-window only** (`src-tauri/src/ipc_guard.rs`, 2026-07-13). Capabilities scope *plugin* commands per window, but every `#[tauri::command]` is registered through one `generate_handler!` for the whole app — so the `invoke_handler` in `lib.rs` is wrapped with a label check: a non-`main` window may call only the commands in `NON_MAIN_WINDOW_COMMANDS` (today: `custom_themes_list` + `load_settings` — both read-only, no caller-supplied path, no secrets), everything else rejects. The detached preview window renders attacker-supplied PDF content and must never inherit the main window's filesystem / keyring / HTTP / git / compile authority. Adding a command to that allowlist is a security decision; the preview's own IPC needs are a bridge event away.
- **Plugin-fs is scoped to the projects subtree, not to Documents** (2026-07-13; closes the deferred finding 30 for the *static* grant). See the fs-plugin gotcha above: static capability entries cover the default root only, the configured root is added to the runtime scope in Rust, and dialog-picked paths are added by the dialog plugin. The `preview` capability grants a *binary read* of PDFs and nothing else (no text read, no dir listing, no writes).
- **Loopback HTTP is not a general egress channel.** `is_allowed_loopback_url` (`integrations/http.rs`) pins plaintext loopback to the two supported local integrations: Zotero's local server (port 23119, `/better-bibtex*` + `/api/*`) and Ollama (port 11434 or the loopback port from `integrations.ai.ollamaBaseUrl`, mirrored into `LOCAL_AI_PORT` on startup + `save_settings`; `/api/*`). An arbitrary-port loopback allowance would hand an injected renderer a localhost port scanner / SSRF surface into every other service on the machine. No credential is bound to a loopback host (`validate_auth_ref_for_host`), and the same check runs on every redirect hop.
- **Tectonic compiles untrusted unless the project is trusted.** `compile.rs::tectonic_args` passes `--untrusted` by default (a `.tex` file is attacker-supplied content) and drops it *only* when the per-machine shell-escape trust grant applies (`trust.rs`), because untrusted mode refuses `-Z shell-escape` and the two together would silently break a trusted build. `--only-cached` (a strictly offline compile, no bundle fetches) rides the `compile.strictOffline` setting — default OFF so a cold cache can still fetch packages; the setting is backend-owned and preserved across settings roundtrips (`settings::preserve_backend_owned`).
- **CSP `connect-src` carries exact origins, never wildcards.** `csp` and `devCsp` in `tauri.conf.json` are complete and standalone — `build.rs` is just `fn main() { tauri_build::build() }` and splices nothing in, so what the config file says is what ships. The Sentry ingest host is the only external origin; everything else is `'self'` / `ipc:` (plus loopback dev servers in `devCsp`). A wildcard origin would hand an XSS payload an exfil endpoint on any attacker-owned tenant of that provider — pin the exact host, and don't reintroduce a build-script CSP overlay.
- **Secure storage never silently mocks.** `keyring` 3.x has no Android backend and falls through to its in-memory `mock` store, where a `set_secret` "succeeds" and the next IPC call reads back `None`. `credentials.rs::ensure_secure_storage` makes any target without a real keystore a hard `SecureStorageUnavailable` error at the boundary. Shipping Android means implementing a Keystore-backed store first — not relaxing this guard.
- **Git is desktop-only, at the dependency level.** `git2`'s `https` feature links openssl-sys on non-Apple unix (including aarch64-linux-android), which kills the Android build. `git2` lives in the `cfg(not(any(target_os = "android", target_os = "ios")))` dependency section, `integrations::vcs` is `#[cfg(desktop)]`, and every `git_*` command in `lib.rs` is gated to match — so the git IPC surface **does not exist** on mobile (calls reject as unknown commands; the frontend must treat VCS as absent there, not as failing).

**Known gaps deferred from the 2026-06-10 audit (re-verified 2026-06-11):**
- **Minor LSP robustness** — duplicate `autocompletion()` config (base config + LSP extension both install it) and best-effort `notify` ordering across async invokes (audit L2/L4) remain. Low impact.
- Cloud sync conflict handling now has a per-file `sync-state.json` manifest (rev + content hash), delete-conflict sidecars, and deletion push; only the two-sided-conflict *winner* decision is still mtime-based, and the loser is always preserved as a `.conflict-*` sidecar. Unsafe remote entries are skipped per-change (telemetry-logged) instead of wedging the delta page.

## Conventions

- **Use npm**, not pnpm or yarn (user preference).
- **No paid tier, no account, no backend — features are never gated.** There is no entitlement layer, no `FeatureGate`, no tier check, no sign-in, and no upgrade or billing surface anywhere in the app. Don't add one, and don't write code that branches on "is this user allowed".
- **Kobalte for a11y primitives** (Dialog, Popover, DropdownMenu, Tooltip, Tabs, Switch, Combobox, Toast) — **not** shadcn/solid-ui (their aesthetic conflicts with the glass design).
- **No emojis** in code, files, or commit messages unless explicitly asked.
- **No `Co-Authored-By:` trailers on commits** — the local git identity is the user; don't append Claude or any assistant as co-author. Applies to direct commits and to any subagent instructed to commit.
- **No new docs/README files** unless requested.
- **No comments explaining what code does** — only *why*, when non-obvious. Don't reference tasks/PRs/callers in comments.
- **Designs are visual truth** — port HTML output, not the prototype's React structure.
- **Themes** swap via `<html data-theme="...">` and `<html data-accent="...">`. Exactly four ship: **Daylight** (default — t1 Desk Lamp light, tuned to `design_files/sample_identity.txt`: ivory paper, charcoal ink, near-black primary, brass selection, seal-red errors), **Lamplight** (t1 dark), **Aurora** (`tokens.css` `:root` baseline, no `data-theme`), **Paper**. Per-theme `--syntax-*` tokens drive CodeMirror colors; `--color-accent-fg` is the text color on `.accent-grad` surfaces; `--color-text-selection` is the selection wash. User **custom themes** (JSON in `<app_data>/themes/`, validated in `themes.rs`) layer extra tokens over a built-in base via `html[data-custom-theme]`. See `src/themes/theme-store.ts` and `design/themes.md`.
