# Frontend notes

Loads when you work under `src/`. The root `CLAUDE.md` has the project-wide rules. Deeper notes live in `integrations/cloud/`, `integrations/references/` and `lib/visual/`.

## Architectural seams

Read these before adding format-specific or integration code, because each one exists so the next format or provider is an addition rather than a rework.

- **`EditorAdapter`** (`adapters/<format>/`) is the per-format glue: compile delegate plus commands. `LatexAdapter` calls `compile_latex`, `TypstAdapter` calls `compile_typst`, both through the leaf `commands/compile-runner.ts` (which breaks the old adapters/actions import cycle). `previewKind` and `cmExtensions` are vestigial, kept for a test fake. **`languageId` is not**: it picks the LSP server via `asLspLanguage(adapter.languageId)` in `EditorScreen`, and a wrong value silently disables LSP for that format with no compile error. The format-to-adapter mapping has a single source, `adapterFor()` in `commands/actions.ts`. Per-file dispatch tables live in `adapters/languages.ts` (extension to language, language to LSP/grammar) and `adapters/format-tables.ts` (prose facts, snippets).
- **`CommandRegistry`** (`commands/`) is wired end to end. `bootCoreCommands()` runs at startup; adapter commands register on project load and unregister on cleanup. Global shortcuts dispatch through `commands/keyboard.ts`, so CodeMirror hardcodes none. Save and compile orchestration lives in `commands/actions.ts`, the single point mapping `project.format` to an adapter. Editor-scoped commands gate on focus being inside `.cm-content` or `[data-editor-shell]`.
- **Integrations** (`integrations/`) is the substrate every third party plugs into. Provider interfaces (`CitationProvider`, `CloudFsProvider`, `AiProvider`, `GrammarProvider`, `TemplateProvider`) live in `integrations/types.ts`; each category has a registry plus an init module that watches `integrationsSettings()` and registers providers reactively. `App.tsx` wires the inits at boot.
- **LSP transport** (`lib/lsp/client.ts` raw, `lib/lsp/cm6.ts` CM6 binding, `stores/lsp-store.ts`). Rust owns the child processes; the frontend talks over Tauri **event channels**, not `invoke`, for streaming traffic. `invoke` is only lifecycle and outbound writes. The CM6 binding is hand-rolled because `codemirror-languageserver` is coupled to a WebSocket transport.
- **AI streaming** (`integrations/ai/stream.ts`): `aiStream(req, signal)` is an AsyncIterable over a per-stream Tauri event channel, calling `ai_stream_abort` when the signal fires. All four providers implement the same `AiProvider` shape; one is active at a time. **`integrations.ai.enabled` defaults OFF** on both sides, so no AI surface renders and no AI traffic leaves until the user turns it on. Do not flip that default.
- **Unified file watcher** (`lib/watcher/client.ts`, `stores/watcher-store.ts`): one Rust `notify` service, an `fsVersion` signal the FileTree reads as a resource key. The watcher **id is unique per start**, because Rust's map `insert` replaces, so a root-derived id let a stale `stop()` remove the live watcher after a fast away-and-back navigation. `.typeward/` paths are stripped in Rust and never reach `paths`, with one carve-out: a write under `.typeward/reviews/` sets the separate `reviewsChanged` flag, which is how a collaborator's comment in a folder-synced project reaches the review store. It is a flag rather than a path precisely so the sidecar still cannot wake the FileTree.
- **Autosave** (`lib/autosave/`) is debounced 500ms into `<project>/.typeward/snapshots/`. The effect body is async and re-entrant (Solid does not await one run before starting the next), so it carries a run-generation guard and `isStale()`, which revalidates a captured `OpenFile` against the live store. `isStale` is deliberately conservative: a closed tab or torn-down project still flushes, and it refuses only when the buffer moved on or a rename repointed the tab.
- **Responsive layout** (`stores/viewport-store.ts`, `components/layout/PaneSwitcher.tsx`): `viewportMode()` flips at 1024px. `TextShell` keeps a desktop corvu Resizable and a tablet single-pane variant. `setActivePane()` is the public lever; `cyclePane()` is gesture-only. Do not add fixed-width assumptions to shells, guard on `isTabletViewport()`.
- **Markdown files** swap the right pane from `<PdfViewer>` to `<MarkdownPreview>` (markdown-it + local KaTeX + DOMPurify). Sandboxed render with a guarded relative-asset rewrite; `file:` URLs, traversal, absolute paths and unknown schemes are rejected. It does not participate in compile.
- **texlive-wasm** (`providers/compile/texlive-wasm-provider.ts`) is the mobile-only WASM LaTeX engine, selected when `compileEngine() === "texlive-wasm"` and hard-gated behind `isTauriMobile()`. `LatexAdapter.compile()` dynamic-imports it so the WASM bridge never enters desktop bundles. Note the naming split: only the npm module specifier is scoped (`@typeward/texlive-wasm`); the engine identifier, asset directories and capability globs are deliberately unscoped and must stay that way.

## Traps

- **Editor view pool.** `screens/editor/shells/text-shell.tsx` keeps up to `POOL_LIMIT` (4) CodeMirror views mounted and display-toggled, so a tab switch never rebuilds CM6's height map. Keyed on `editorKey` (`path::adopt::lsp::grammar`) but capped to **at most one live view per file PATH**: an LSP attach or grammar toggle supersedes that path's view (evict then create), never doubles it, or the LSP gets a second `didOpen` for one URI and the crash-restore adopt guard is defeated. **Each view is bound to its own file, never the global active one**: `onChange` writes via `updateFileContentByPath(entry.path, ...)`, and extensions take `entry.relPath` plus that entry's content, so a background view's edit cannot leak into the active file. Only the active view owns the `editor-view-store` handle and feeds the cursor signals. Never swap a different file's content into an existing view.
- **`CodeMirror`'s `defaultKeymap` binds `Mod-Enter` to `insertBlankLine`**, and it is filtered out because the global router also dispatches Mod+Enter as compile. Without the filter every compile shortcut injected a blank line. No new keymap source may reintroduce it.
- **PDF.js `RenderingCancelledException` is benign**, fired whenever a render is superseded. `PdfViewer` uses a generation counter and swallows it. Do not surface it as an error.
- **Persisted settings enums are validated at the load boundary.** `settings-store.ts` runs every enum-shaped field through `validEnum(raw, allowed, fallback)`, so a stale value from a removed variant degrades to the default instead of rendering an unthemed app. Register any new persisted enum there.
- **`widgets/` is intentionally unmounted, not dead code.** The registry and builtins were removed from `ProjectsScreen` but kept, along with the `dashboard*` settings, for its return. Do not delete as unreferenced.
- **"Open with Typeward" is a handshake, not an emit** (`lib/open-with.ts`). A cold launch hands Rust the path before the webview exists, and on macOS the Apple Event is the only route. Tauri events are fire-and-forget to current listeners, so emitting immediately lost the open. Rust parks the path; the frontend drains it with `take_pending_open` as its listener mounts, which also marks the frontend ready. Do not reintroduce a sleep-and-hope delay.
- **Use `describeIpcError` from `lib/errors.ts`**, not `String(e)`, when surfacing IPC errors. Rust rejects with a plain Display string, so a string rejection is the message verbatim. `recordError(kind, summary, detail)` is a local `console.error` wrapper only; nothing is persisted or transmitted.
- **The Typst syntax highlighter is hand-rolled and intentionally minimal.** `adapters/typst/typst-language.ts` is a small CM6 `StreamLanguage` covering comments, strings, math, `#funcs`, headings and emphasis. When tinymist's structured tokens become consumable over the LSP transport, prefer those rather than growing this parser.
- **`public/boot-theme.js` is a classic script served verbatim from `public/`**, deliberately outside the Vite bundle graph so the theme re-tint runs before the app bundle even in release builds. It is external because the CSP forbids inline scripts. Together with `backgroundColor` in `tauri.conf.json` it stops the pre-paint flash, so dark-theme users never get a cream flash. Do not move it into the bundle.
- **texlive-wasm assets live in two places on purpose.** The engines go under `public/texlive-wasm/` because the worker `import()`s the glue and `fetch()`es the wasm *by URL*, and only the app's own origin satisfies `script-src 'self'`. The TeX Live tree goes under `src-tauri/resources/` and is read lazily off disk, since it is far too large for the bundle graph. It is bundled on **mobile only**.

## macOS and WKWebView

The app was developed against WebView2/Chromium. WKWebView is Safari-engine and version-locked to the OS, floor Safari 16.4.

- **pdfjs stays on the LEGACY build.** The modern build touches the `Iterator` global at module eval; WKWebView below Safari 18.4 throws, the EditorScreen import fails, and project open dead-ends at the ErrorBoundary. Do not "simplify" those imports.
- **WebKit needs the `-webkit-` prefix** for `user-select` and, before 18.0, `backdrop-filter`. Every declaration needs the prefixed twin, or body's inherited `-webkit-user-select: none` kills PDF text selection. **The prefix alone is not enough: the CONTAINER has to opt in, not just the selectable leaves.** Chromium lets a descendant re-enable selection under a `user-select: none` ancestor, so WebView2 hides the mistake entirely; WebKit treats that ancestor as a selection boundary and refuses to start a selection inside it. `.pdf-text-layer` had `text` on its spans and nothing on the wrapper, and PDF selection (with the I-beam, PDF comments and review anchoring) was dead on WKWebView and WebKitGTK while Windows looked correct. Any new selectable surface under `body` needs the declaration on the subtree root. Trackpad pinch arrives as proprietary `gesturestart`/`gesturechange`; WebKit never synthesizes ctrl+wheel. `requestIdleCallback` does not exist, guard it.
- **`backdrop-filter` is force-disabled on macOS** by a kill rule in `themes/utilities.css`. The window-server composite renders any backdrop-filtered element as an opaque gray slab in every configuration, while the web-process render and `takeSnapshot` look correct, so **never verify this class of bug with takeSnapshot or DOM probes**. Floating glass surfaces therefore carry an explicit `--color-popover-bg` so legibility never depends on frost, and **ambient blobs must never use `filter: blur()`** (WebKit degrades large radii to near-invisibility, and `blur(120px)` rendered the layer black). Keep new decorative blurs at or under ~40px, or bake them into gradients.
- **`MarkdownPreview`'s DOMPurify `ALLOWED_URI_REGEXP` must keep `asset:`**, since `convertFileSrc` yields `asset://localhost/...` everywhere except Windows.
- **wry's `zoomHotkeysEnabled` is WebView2-only.** Window zoom is the `core.zoomIn` / `zoomOut` / `zoomReset` commands stepping the persisted `uiScale` (90 to 150), not a webview accelerator.
