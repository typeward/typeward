# Status

**App build phases (original plan):**

- **Phase 0** — skeleton (Tauri+Solid+TS, Tailwind v4, Kobalte/corvu/router/lucide, themes, baseline tests).
- **Phase 1** — vertical slice complete on desktop: four screens fully ported with visual passes; multi-tab editor; LSP transport + hand-rolled CM6 integration (texlab/tinymist when on PATH); real LaTeX compile via system TeX with `latexmk → pdflatex` fallback or Tectonic; PDF.js preview with toolbar (Recompile, page nav, zoom dropdown); LogsDrawer with Logs + Issues tabs; autosave + crash recovery; telemetry capture; first-run onboarding redirect; unified file watcher driving FileTree refresh. Tectonic sidecar bundled via `externalBin: ["binaries/tectonic"]` (enabled 2026-05-15); binary fetched per-dev-host with `npm run fetch:tectonic`.
- **Phase 2 — complete** (2026-05-12). CommandRegistry binding (boot core commands + adapter register/unregister on project load, global keyboard router with scope/when gates, shared `<CommandPalette />` at App root), Typst adapter routed through the single `actions.adapterFor()` (imported by `EditorScreen`; the duplicate mapping was removed 2026-07-02), SyncTeX forward (Mod+J → PDF pulse-ribbon) + inverse (shift+click on PDF → editor cursor; double-click became the primary gesture 2026-06-11). Smart per-page PDF diff and sync-to-cursor toggle were intentionally skipped per user direction. Quarto was scoped in then removed (2026-05-12).
- **Phase 3 — INCOMPLETE, gated** (scaffolding 2026-05-13; status corrected 2026-07-13). The tablet *shell* landed and works; the tablet *target* has never run — no APK has been built on an emulator or device. Three blockers: (1) the Android build fails in `openssl-sys` (dragged in by `git2`; fix = cfg-gate git out of mobile, in flight), (2) the WASM compile path passed no `enginePath` so engine init threw on every mobile compile (renderer half fixed 2026-07-13, unproven on a device), (3) OS-keyring credentials silently don't persist on Android. Don't call this phase done until an APK compiles a document on hardware. iPadOS is untouched (macOS-only work).
  - **Responsive layout**. `src/stores/viewport-store.ts` derives `viewportMode` (desktop ≥1024 / tablet <1024) + `activePane` (sidebar/editor/preview) + `logsSheetOpen`. `TextShell` branches on `isTabletViewport()`: desktop keeps the corvu 3-pane Resizable; tablet collapses to a single `<Switch>`-rendered pane plus `<PaneSwitcher />` (bottom segmented control, 44px+ tap targets) and a slide-up `LogsSheet` overlay. `src/lib/gestures.ts` `installSwipeListener` cycles panes on touch/pen horizontal swipe (>70px, ratio-gated so vertical scrolls don't trigger). Bumped tab strip + close-button hit areas in `CenterPane` when in tablet mode. File-select on tablet auto-swaps the active pane back to "editor".
  - **texlive-wasm WASM CompileProvider**. `src/providers/compile/texlive-wasm-provider.ts` wraps `texlive-wasm` (Typeward's MIT-licensed sibling project — a `file:../texlive-wasm` checkout until 2026-08-05, the npm package `@typeward/texlive-wasm` since): walks the project tree for `.tex`/`.bib`/`.cls`/`.sty`/`.bst`/`.def`/`.ldf`/`.fd`/`.cnf`/`.clo`/`.aux` as UTF-8 and `.png`/`.jpg`/`.jpeg`/`.pdf`/`.gif`/`.eps` as `Uint8Array` via the `read_project_binary_file` IPC (capped 200 files / 10 MB combined), auto-enables BibTeX when any `.bib` is found, writes the PDF via the project-scoped `write_project_binary_file` Tauri command, sniffs SyncTeX magic bytes and writes either `.synctex.gz` or `.synctex` next to the PDF so the existing `synctex` CLI resolves forward/inverse against texlive-wasm output, and reuses the Rust `parse_latex_log` extractor via the `parse_latex_log_cmd` IPC so diagnostics match the desktop shape. `CompileEngine` is `"system-tex" | "tectonic" | "texlive-wasm"`; `LatexAdapter.compile()` dispatches via dynamic import so the WASM bridge stays out of desktop bundles when unused. Mobile-only — not selectable on desktop. Settings → Editor → Compilation shows an install-status badge with the exact download-assets commands when an asset is missing.
  - **Android build pipeline — scaffold only, never built**. `tauri android init` ran cleanly with `JAVA_HOME` pointing at Android Studio's bundled JBR 21 (Java not on PATH on the dev host — prefix `$JAVA_HOME\bin` before Android commands). Generated `src-tauri/gen/android/` with Gradle wrapper, app module, and gitignores for build artifacts. All four Android Rust targets (`aarch64`, `armv7`, `i686`, `x86_64`-linux-android) installed. `Cargo.toml` already had `crate-type = ["staticlib", "cdylib", "rlib"]`. **An actual APK has never been produced**: the build fails in `openssl-sys` (via `git2`), and Android keyring persistence is unimplemented. Emulator/device setup is still user-driven on top of that.
- **Phase 4 — superseded (2026-05-22), remainder dropped (2026-08-03)**. The original backend folder-sync/collab/licensing phase was retired; third-party cloud storage shipped in the integrations program instead, and the narrowed auth+entitlements successor (Integ Phase 7) was itself removed when the project went source-public. Files stay local-first and there is no Typeward-operated backend of any kind.
- **Scope narrowed (2026-05-20)** — supported project formats reduced to LaTeX + Typst. Markdown-as-project, R Markdown, and the notebook experience were removed. `.md` files inside any project now get a live in-app HTML preview. See `docs/ntb_feature.md` (archival notes).

**Integrations program (2026-05-22 → 2026-05-24):** approved plan at `~/.claude/plans/research-and-completely-plan-resilient-brook.md`. Phases 0–6 shipped and are live. Phase 7 (accounts + entitlements) shipped 2026-05-23 and was removed wholesale 2026-08-03 — see its row below. In-app billing (the old 7.6 Stripe webhook) had already been dropped 2026-06-13 in favour of website purchases; that model went away with the paid tier itself. **The app today has no billing, no plans, no tiers, and no account link.**

- **Integ Phase 0 — Foundations** (2026-05-22). Rust: `reqwest` HTTPS, OS keyring, PKCE OAuth with `axum` loopback callback, `opener` plugin + capability. Frontend: provider interfaces, `runOauthFlow` driver. Settings + Project schemas extended (`IntegrationsSettings` + `ProjectIntegrations`, both `#[serde(default)]`-additive). (Also shipped the free-tier entitlement fallback and `<FeatureGate>` / `<UpgradePrompt>` — both deleted 2026-08-03.)
- **Integ Phase 1 — References** (2026-05-22; JabRef removed 2026-06-13). Zotero (Better BibTeX local probe + Web API key), Mendeley (OAuth PKCE; flagged as maintenance-mode), DOI/arXiv lookup (no auth — `doi.org` content negotiation; modern arXiv via synthesized `10.48550/` DOI, older arXiv via Atom). Aggregator writes `<project>/.typeward/citations/library.bib`; texlive-wasm + texlab/tinymist pick it up automatically. ReferencesPanel sidebar tab + DoiLookupDialog + per-provider settings card. - **Integ Phase 2 — Cloud storage** (2026-05-22; hardened 2026-05-24; WebDAV added 2026-06-20; **Dropbox removed 2026-08-05**). Shipped with Dropbox (longpoll cursor); **WebDAV is the only backend today** — Nextcloud, ownCloud or any WebDAV host, needing no registered app and no client id. The sync engine, status badge, ConflictResolverDialog and new-project Cloud branch are provider-agnostic and survived every removal unchanged. Remote paths are normalized before cache IO. (OneDrive (Graph delta) and Google Drive (`drive.file`) were built then removed 2026-06-14, iCloud 2026-06-20 — use their native desktop sync apps pointed at a local projects folder; OneDrive is on Windows by default. - **Integ Phase 3 — Git/GitHub/Overleaf** (2026-05-22; hardened 2026-05-24). libgit2 via `git2` (12 IPCs, all spawn-blocking); GitHub device-flow OAuth (token shared with libgit2 in keyring `git.github.com`); Overleaf zip import via `zip` crate (zip-slip guarded); the Overleaf git-bridge clone reuses `git_clone`. CommitPanel (SCM sidebar), GitStatusBar (TopBar), CloneDialog with provider sniffing, Author identity + GitHub sign-in cards in Settings. Pull is fast-forward only and refuses dirty worktrees.
- **Integ Phase 4 — AI providers** (2026-05-22; hardened 2026-05-24). One Rust streaming task with format-specific parsers (Anthropic SSE / OpenAI SSE / Gemini SSE / Ollama NDJSON); abortable via `ai_stream_abort`. Frontend AsyncIterable adapter (`aiStream`). Empty `AiView` filled with real streaming chat (model picker, stop button, Mod+Enter send). AI settings card paste-key probe → ready. OpenAI/Anthropic/Gemini keys attach via Rust `authRef`.
- **Integ Phase 5 — Grammar** (2026-05-23). Harper via `harper-core` (Rust-native, in-process, zero network). `grammar_check(text, file, syntax)` IPC, CM6 `@codemirror/lint` linter (400ms debounce, 3 quick-fix actions per lint), gated on `integrations.grammar.enabled`.
- **Integ Phase 6 — Templates** (2026-05-23). Manifest-driven (`template.json` with `variables[]` + `files[]`), Handlebars-subset `{{var}}` substitution, zip-slip path guard. 4 built-in templates shipped (latex article / IEEE conference / beamer, typst article) under `src-tauri/resources/templates/`. `<TemplateGallery>` two-stage dialog in new-project flow. Save-as-template landed 2026-06-10 (`template_save` IPC + `core.saveTemplate` → `<SaveTemplateDialog>`); custom templates can also be hand-authored under `<app_data>/templates/custom/<id>/`.

**Modules that postdate the last full doc refresh (added to the map 2026-07-29 audit):**
- **Pandoc export** (`src-tauri/src/export_pandoc.rs`, `ExportMenu.tsx`) — Word `.docx` + standalone HTML via a PATH-detected `pandoc` (resolved through `detect::resolve_program`); output lands in `.typeward/build/` and the frontend copies it out through the dialog-scoped fs plugin. **Bounded** through the shared runner (timeout + tree-kill + output cap) like compile — pandoc's LaTeX reader does macro expansion, so it is untrusted-input-shaped. HTML export is deliberately NOT `--embed-resources` (that would give an untrusted document an unallowlisted network/local-file embedding channel). Requires pandoc ≥3.1.12 for Typst input.
- **PDF annotation flattening** (`src-tauri/src/export_annotated.rs`, `lopdf`) — bakes review-thread comments into the compiled PDF as `/Text` annotations, placed via per-annotation SyncTeX forward lookups (bounded runner; capped at 500 annotations). Reads the machine-local `.typeward/reviews/comments.json` sidecar.
- **Project history** (`src-tauri/src/history.rs`) — content-addressed gzip version blobs under app-data, per-project mutex-guarded; `HistoryPanel` browses/restores. Restore takes a forced safety snapshot (bounded read ceiling).
- **Shell-escape trust** (`src-tauri/src/trust.rs`) — per-machine grant store keyed by canonical root, kept OUTSIDE the project (a cloned `project.json` can't grant itself). Granting requires a native Rust confirmation dialog the renderer cannot fabricate; `LatexAdapter.ensureShellEscapeTrust` reads back the effective decision.
- **TODO scan** (`src-tauri/src/todo_scan.rs`, `todo-store.ts`, `TodoPanel`) — TODO/FIXME/NOTE marker scan of the project tree; results tagged with their root so a project switch can't surface stale markers.
- Grammar dictionary/ignore commands (`grammar/config.rs`) are async + spawn_blocking (fsync'd writes off the main thread) and the curated LintGroup is cached across `grammar_check` calls.

**Dropbox removed, texlive-wasm from npm (2026-08-05) — the latest structural change:**

- **Dropbox is gone.** The provider, its OAuth flow, `VITE_DROPBOX_CLIENT_ID`, the `*.dropboxapi.com` outbound-allowlist entries, the `www.dropbox.com/oauth2/authorize` OAuth + opener allowlist entries, and all its UI were deleted. **WebDAV is now the only cloud sync backend** — `CloudProviderId` is just `"webdav"`. It survived because it needs nothing registered: any WebDAV host (Nextcloud, ownCloud) works with a URL and an account, no client id, no vendor API to track. The generic `SyncEngine`, conflict resolution and the `.remote-cache` layer are untouched.
- **Projects still bound to Dropbox degrade cleanly.** `readCloudOrigin` (`src/integrations/cloud/registry.ts`) returns null for any provider this build no longer ships, so a `.typeward/project.json` that still says `cloudOrigin.provider === "dropbox"` reads as *not cloud-backed*: the folder opens, edits and compiles as a plain local project, nothing on disk is rewritten, and no sync chip is shown. It simply stops syncing.
- **Mendeley is now the only OAuth provider wired up, and it is a *confidential* client** (client secret in the keyring, fixed loopback redirect pasted from the user's registration). No PKCE public client remains in use — the PKCE machinery in `integrations::oauth` is intact but nothing shipped drives it. GitHub still signs in with its own device flow. `.env.example` is down to `VITE_MENDELEY_CLIENT_ID` + `VITE_GITHUB_CLIENT_ID`.
- **`texlive-wasm` now installs from npm as `@typeward/texlive-wasm`, pinned `0.2.4-alpha`.** The `file:../texlive-wasm` sibling dependency, the `config.texliveWasm` commit pin in `package.json` and the "check out and build the sibling repo" steps in build.yml / release.yml / tests.yml are all gone. **A plain `npm install` now works from a bare clone** — the last dependency that required a second checkout. Module specifiers in `src/` moved to the scoped name; the CLI is still `npx texlive-wasm download-assets ...` because the package's bin name is unchanged.
- **The engine identifier deliberately did not change.** `"texlive-wasm"` is still the `CompileEngine` union member and still names the asset directories under `public/` and `src-tauri/resources/`, so persisted settings, the mobile engine lock and the asset-fetch commands are all untouched. Only module specifiers moved.
- **Verified green:** `npx tsc --noEmit`, `npx vitest run` (65 files, 527 tests), `cargo clippy --all-targets --locked -- -D warnings`, `cargo test` (273 tests), `npm run build`, `npm run check:bundle`.
