# Projects screen — library redesign (2026-07-05, approved)

Six items, numbered to match the original request. Scope decisions (user-approved, do not relitigate): TopBar becomes the real library search on the Projects screen; sort + view controls move to the header subtitle line; **starring is removed entirely**; the Library rail becomes five categories (All / Your / Shared / Archived / Trashed) with an in-app soft-trash ("Shared with you" ships now with a coming-soon empty state; Trash = restore + permanent-delete-to-Recycle-Bin); sidebar `+` alignment fix; left-aligned new-project affordances + icon-only DeadlineEditor; richer card/row metadata (relative times, sync/git chip, space tint).

Current state: `src/screens/projects/ProjectsScreen.tsx` (1436 lines) renders header (L281-291, right side of the justify-between row empty) → `LibraryToolbar` (search input + sort listbox + view toggle) → grid/list. Filter pipeline `visibleProjects` L185-242 (archive split → selection → search → sort). Rail = All/Starred/Archive + Spaces + Tags (`LibrarySidebar.tsx`). Delete = confirm dialog → `delete_project` → OS Recycle Bin. TopBar's centered "search" is a button that opens the command palette, not an input. No trash concept, no shared concept, no relative-time helper (`src/lib/time.ts` does not exist — verified).

## 1. Data model

One additive field in `.typeward/project.json` (Rust `src-tauri/src/project.rs`, after `archived` ~L42):

```rust
/// In-app soft-trash stamp (epoch ms). `Some` hides the project from every
/// library view except Trashed and blocks opening; cleared on restore.
/// Epoch ms rather than bool so a future auto-purge can age entries.
#[serde(default, skip_serializing_if = "Option::is_none")]
pub trashed_at: Option<i64>,
```

TS mirror `src/adapters/types.ts`: add `trashedAt?: number`, **delete `starred?: boolean`** (L23).

Starred removal is a plain field deletion: `Project` derives `Deserialize` without `deny_unknown_fields`, so legacy project.json files carrying `"starred": true` load fine (key ignored) and the key drops on the next metadata write. No migration; star data is deliberately discarded. Rust `Project` literals to touch: `duplicate_project` (project.rs L562-575 — replace `starred: false` with `trashed_at: None`); creation paths use `..Default::default()` and need nothing.

Auto-purge is explicitly NOT in scope — `trashedAt` just makes it possible later.

## 4. Category rail semantics

`src/components/projects/library-selection.ts`:

```ts
export type LibrarySelection =
  | { kind: "all" } | { kind: "yours" } | { kind: "shared" }
  | { kind: "archive" } | { kind: "trash" }
  | { kind: "space"; id: string } | { kind: "tag"; tag: string };
```

(`sameSelection` needs no change — new kinds are parameterless.)

| Rail row | Icon | Predicate (over `projects()`) | Search applies | Empty state |
|---|---|---|---|---|
| All projects | Folder | `!isTrashed && !archived` | yes | existing "No projects match" (filters) / plain grid |
| Your projects | User | `!isTrashed && !archived && isYours` | yes | same as All (today identical to All by definition) |
| Shared with you | Users | `!isTrashed && !archived && isShared` → always empty today | n/a | dedicated friendly state: "Nothing shared with you yet — sharing and collaboration are coming soon." No Clear-filters button. |
| Archived projects | Archive | `!isTrashed && archived` | yes | existing |
| Trashed projects | Trash2 | `isTrashed` (archived or not) | yes (within trash) | "Trash is empty — projects you move to the trash can be restored or deleted permanently." |
| Spaces / Tags | (unchanged) | membership ∧ `!isTrashed && !archived` | yes | unchanged |

Pipeline rewrite (ProjectsScreen L185-242) — trash split becomes step 0:

```ts
let list = projects().filter((p) => isTrashed(p) === (sel.kind === "trash"));
if (sel.kind !== "trash")
  list = list.filter((p) => !!p.archived === (sel.kind === "archive"));
if (sel.kind === "yours") list = list.filter(isYours);
else if (sel.kind === "shared") list = list.filter(isShared);
else if (sel.kind === "space") ... // unchanged
else if (sel.kind === "tag") ...   // unchanged
// search + sort unchanged
```

Trash view keeps the global sort control (simplest; revisit if trash gets large). `knownTags` memo (L178-182) and the sidebar space/tag counts filter out trashed. Header subtitle count = untrashed count. `emptyState` gains two special branches: `shared` → coming-soon state, `trash` → trash-empty state (both bypass "Clear filters" when no search is active).

**Trashed exclusion outside the screen** (all one-line `!isTrashed(p)` filters):
- `src/components/CommandPalette.tsx` L99-100 (recent projects rows).
- `src/components/editor/ProjectSwitcherMenu.tsx` L28-31.
- `src/widgets/builtins.tsx` (recent-projects widget — unmounted but kept; update for consistency).

**A trashed project cannot be opened.** Two guards:
1. Library: clicking a trashed card/row opens `RestorePromptDialog` ("*{name}* is in the trash. Restore it to open it." — Cancel / **Restore & open** primary → `setTrashed(root, false)` then navigate).
2. Chokepoint: `EditorScreen.tsx` open effect (L96) — after `openProject` resolves, `if (p.trashedAt != null)` → `notifyError("Project is in the trash", "Restore it from the library to open it.")`, run the existing failure-cleanup branch, `navigate("/projects")`. Covers palette, switcher, and `/editor?path=` deep links; also means `touchProjectOpened` never stamps a trashed project. No Rust-side gate on `open_project` (frontend chokepoint only — flagged below).

**Cloud sync + trash**: the engine (`cloud/init.ts`) keys off editor-store `project()`, which survives navigating back to /projects (EditorScreen `onCleanup` L163-169 does not `setProject(null)` — verified), so an engine can be live while the user trashes that very project from the library. Fix: in ProjectsScreen's trash handler (and the permanent-delete handler — today's `remove()` has the same latent gap), if `editorProject()?.rootPath === p.rootPath` → `setProject(null)` after the setter succeeds; the init effect reconciles the engine down. This is the "sync engine skips trashed projects" guarantee: engines only exist for the open project, trashed projects can't be opened, and trashing the open project tears its engine down. The remote copy is untouched (soft-trash never deletes anything).

## Edge cases

- Legacy project.json: `trashedAt` absent → not trashed; stale `"starred"` keys ignored on read, dropped on next write (test added).
- **patch() re-default**: restore clears `trashedAt`, which `skip_serializing_if` omits from the returned Project — the explicit `trashedAt: next.trashedAt` in `patch()` is load-bearing (same class as unstar/unarchive).
- Trashed + archived: shows only in Trash; restore preserves `archived` → lands back in Archived projects. Correct and cheap.
- Trashed + cloud-synced: soft-trash touches only project.json; the remote copy stays. Engine handling per section 4; permanent delete keeps the existing "remote copy stays untouched" caveat.
- Trash the project currently open in the editor (via library while its runtime persists): `setProject(null)` guard tears down engine/watcher consumers; same guard added to permanent delete (fixes a pre-existing latent gap).
- Deep-link `/editor?path=<trashed>`: EditorScreen chokepoint bounces to /projects with a toast.
- Space/tag deleted-selection guard (ProjectsScreen L114-119) unchanged; new kinds can't strand.
- Duplicate: source trashed → copy has `trashed_at: None` (and duplicating from trash isn't reachable in UI anyway).
- ProjectWordCount in trash view still reads the root file (folder exists on disk) — harmless.

## Open flags (resolve at implementation)

- **`+` alignment nudge**: `-mr-1` is derived from box math (20px box, 12px glyph, 8px columns); confirm visually at both densities.
- **Restore & open** as the single primary action of the restore prompt (vs a restore-only button) — recommendation; cheap to change.
- **No Rust gate on `open_project` for trashed projects** — frontend chokepoint only. If defense-in-depth is wanted, a `trashed_at` check in Rust `open_project` is a 5-line add, but then restore-adjacent tooling must never rely on opening.
- Row tag chips behind `hidden xl:flex` — drop them entirely if rows feel crowded in review.
- "Move to trash" success toast: plain `notifySuccess`, no undo (toast service has no action-button support — adding one is out of scope).
