# Editor — feature completion plan (2026-07-03, approved)

Eleven items, numbered to match the original request. Key research (verified 2026-07-03): Harper ships first-party `harper-tex` + `harper-typst` crates (2.5.0; requires upgrading our pinned harper-core 0.59 → 2.5); harper-core 2.5 exposes `LintKind` (20 variants with CSS-safe keys), serde-serializable `IgnoredLints`, `MutableDictionary`/`MergedDictionary`, and 5 English dialects. Pandoc reads Typst input since ~3.1.12 (`pandoc` is already probed in `detect.rs`). `lopdf` (new dep) is the right crate for adding annotations to existing PDFs (`pdf-writer` is create-only). pdfjs-dist ^6.0.227 exports the `TextLayer` class (`render()`/`update({viewport})`/`cancel()`, `textDivs`/`textContentItemsStr`).

User-approved decisions: PDF highlights are **only** the gesture/representation for review + TODO threads (no standalone highlight type); LaTeX build settings are **curated presets + flags** (not LaTeX-Workshop-style custom recipes).

## 1. Refs tab: hide unless available or configured

- New `src/integrations/references/availability.ts`: shared session-cached probe — `refsAvailability(): "unknown" | "some-ready" | "none-ready"`, `readyProviders()`, `refreshAvailability()`. A `createRoot`-wrapped resource keyed on `[citationProviders(), probeTick]` running the `status()` fan-out `ReferencesPanel.availableRes` does today. While loading it returns the previous settled value — the tab never flips to hidden mid-probe. No probe when zero providers are registered (no IPC on free installs).
- `ReferencesPanel` switches to the shared module. The sidebar gate becomes `citationProviders().length > 0 && refsAvailability() !== "none-ready"` (registry as config truth, replacing the raw-settings duplication). Existing bounce-to-Files + `measureTabs` effects already track the gate.
- Bias: configured users see the tab instantly; it disappears only after a definitive all-unreachable probe; the panel's Refresh re-probes.

## 2. Outline: complete implementation

- LSP capability: `documentSymbol: { hierarchicalDocumentSymbolSupport: true }` in `src/lib/lsp/cm6.ts` (texlab + tinymist both support it).
- New `src/lib/lsp/symbols.ts`: `requestDocumentSymbols(session, uri) -> OutlineItem[] | null`, handling hierarchical `DocumentSymbol[]` and flat `SymbolInformation[]`; a STRUCTURE_KINDS allowlist drops label/reference noise (verify texlab/tinymist kinds empirically at implementation; invert to a denylist if fragile).
- New `src/lib/outline/parse.ts` (unit-tested regex fallback): LaTeX `\part..\paragraph` (+ starred forms, balanced-brace titles), Typst `^=+ ` headings, Markdown `#` headings with fence skipping.
- New `src/components/editor/OutlinePanel.tsx` replacing the stub: resource keyed on `[activeFile, ~500ms-debounced content, lspReady]`; LSP first, regex fallback on null/error/empty; nested list with per-node collapse; click → `setCursorLine(item.line)` via editor-view-store (the outline always describes the active file); active-section highlight = last DFS item with `line <= cursorLine()`.
- UI stays the collapsible footer region (state already lifted to the shell); content grows to `max-h-[40%]` with internal scroll.
- Accepted limits: LSP text is stale by its 200ms didChange debounce; verbatim `\section` false-positives affect the regex fallback only.

## 3. Reviews + TODOs: complete implementation

**Reviews (thread targeting)**: replace the boolean `requestReviewPanel` with a payload intent (`{ threadId?, generation }` + a `focusedThreadId` consumable). The gutter click passes its threadId (text-shell currently ignores it); `ReviewPanel` effect ensures visibility (scope → "all" for other files, `showResolved` for resolved threads), expands the thread, scrolls via `data-thread-id`, then clears.

**TODO tab (Rust scan)**: new `src-tauri/src/todo_scan.rs` — `scan_project_todos(project_root) -> Vec<TodoItem { file, line, kind: "todo"|"fixme"|"note", text (≤200 chars) }>`; spawn_blocking + ensure_registered; walk via the existing `templates::collect_project_files` (already skips `.typeward`/`.git`/`node_modules`/symlinks); extensions tex/typ/md/bib/txt; caps 500 files / 1 MB per file / 1000 items; hand-rolled line scanning (no regex dep): keywords in `%` comments + `\todo{...}` for tex/bib, `//` for typ, single-line `<!-- -->` for md; TODO/FIXME/NOTE at word boundary (covers `%! TODO:`).

- New `src/stores/todo-store.ts`: resource keyed on `[project root, ~500ms-debounced fsVersion]` (saves bump fsVersion via the watcher — no extra hook). `todoCount()` feeds the tab badge.
- New `src/components/editor/TodoPanel.tsx`: flat list (kind chip TODO amber / FIXME red / NOTE neutral + text + `file:line` mono chip), click → `requestGotoSource`. **Seam**: the panel renders a `TodoEntry` union (`{source:"scan"} | {source:"thread"; thread: CommentThread}`) — v1 populates scan only; PDF-created todo-kind threads (item 10) plug into the thread branch and click-route to `requestReviewPanelIntent(thread.id)`.
- Accepted: scans disk, not dirty buffers (a just-typed TODO appears after save/autosave).

## 4. Per-project LaTeX build controls (bottom-left status bar)

**Data model**: `Project.build?: ProjectBuild { engine?: "pdflatex"|"xelatex"|"lualatex"|"tectonic"; shellEscape?; synctex?; stopOnFirstError?; autoCompile? }` — additive in project.json, tolerant on read (unknown engine = unset), validated on write. New IPC `set_project_build` mirroring `set_project_deadline`. Precedence: project override → global default (`system-tex` maps to `pdflatex` in the resolver; mobile forces texlive-wasm). New `src/adapters/latex/build-config.ts` `effectiveBuild(p)` single resolver (unit-tested), consumed by LatexAdapter, actions.ts (auto-compile + the texlive-wasm synctex branches), and the sidebar engine pill.

**Compile IPC**: `compile_latex(app, project, options: Option<BuildOptions>)` — replaces the old engine/halt params (single call site). `BuildOptions { engine: LatexEngine (strict serde enum), shell_escape, synctex, halt_on_error }`. Flag mapping = fixed vectors selected by enum match (argument-injection invariant): latexmk `-pdf` / `-xelatex` / `-lualatex` (never `-pdf` alongside the latter two) + conditional `-synctex=1` / `-halt-on-error` / `-shell-escape`; the direct-binary fallback becomes engine-matched (pdflatex/xelatex/lualatex); tectonic gets conditional `--synctex` + `-Z shell-escape` (verify Tectonic 0.15 support at implementation; error rather than silently drop).

**Shell-escape trust (workspace-trust analogue)**: `<app_data>/shell-escape-trust.json` `{ entries: { <canonical-root>: "granted"|"denied" } }` — stored outside the project so a cloned project.json with `"shellEscape": true` cannot pre-grant itself. Rust `compile.rs` is the enforcement chokepoint: `-shell-escape` is added only when requested AND granted; requested-but-untrusted returns an actionable error. New `src-tauri/src/trust.rs` + `shell_escape_trust_get/set` IPCs (ensure_registered). Frontend: first compile with shellEscape requested and trust unset → `ask()` dialog ("lets the document run arbitrary programs during compile — allow on this machine?"); deny persists and compiles without the flag (no nagging); the popover shows trust state and can flip it (denied → granted re-prompts once).

**UI**: new `src/components/editor/BuildMenu.tsx` in the StatusBar left cluster (LaTeX projects only): mono button (e.g. `pdfLaTeX ⌄`), popover opens upward (installDismiss + listbox-nav, like the zoom dropdown): engine listbox, divider, Switch rows (shell-escape with warning subtitle + trust hint, SyncTeX, Stop on first error, Auto-compile) + "Reset to defaults" footer (`setProjectBuild(root, null)`). Optimistic update; `setProject(updated)` on success so the sidebar pill reacts. The global engine row in Settings is reworded to "Default for projects without their own build settings". **Output-directory profile deferred** (latexmk `-outdir` relocates `.synctex.gz` and breaks relative-path matching in synctex resolution plus PdfViewer/export paths — cleanliness-only win, own feature later). Typst: no status-bar item v1.

## 5. Sidebar tabs: icons when narrow

All in `EditorSidebar.tsx`. Icons: Files=Files, Refs=BookMarked, SCM=GitBranch, Review=MessageSquare, TODO=ListTodo. A visually-hidden always-full-labels clone strip is what `measureTabs()` measures — the natural width stays known while compact renders (avoids the stale-width trap; `createSidebarResize` behavior unchanged). A ResizeObserver on the visible strip flips `compact` when `clientWidth < naturalWidth`, expanding back at `naturalWidth + 8` (hysteresis). Compact tabs: icon (size 14) + count badge, `aria-label` + `title` tooltip, same active underline and tab semantics.

## 6. Harper: Grammarly-like grammar for LaTeX and Typst

**Rust** (`integrations/grammar/mod.rs` rework + new `config.rs`):
- Cargo: `harper-core = "2.5"`, `harper-tex = "2.5"`, `harper-typst = "2.5"`. The 0.59→2.x migration risk is confined to this module.
- Parser routing by syntax (stop discarding it): PlainEnglish / Markdown / harper-tex / harper-typst. Add `Markdown` to `GrammarSyntax` on both sides; `languages.ts` maps markdown → "markdown".
- Managed `GrammarState` (RwLock): user dictionary words + `IgnoredLints` + a cached `LintGroup` keyed by (dialect, dictionary generation). Dictionary = `MergedDictionary(curated FST + MutableDictionary)`. Persistence: `<app_data>/grammar/dictionary.txt` + `ignored.json` (atomic writes, lazy-load, write-through).
- Wire shape: `GrammarDiagnostic` gains `kind` (LintKind key) + `contextHash` (u64 as decimal string). Apply `remove_ignored` before serializing. Severity mapping: Spelling/Typo/Grammar/Agreement/BoundaryError/Malapropism/Eggcorn/Capitalization/Punctuation → warning; Style/Enhancement/Readability/Redundancy/Repetition/WordChoice/Formatting/rest → info. Dialect passed per call: `grammar_check(text, file, syntax, dialect)`.
- New IPCs: `grammar_add_word`, `grammar_remove_word`, `grammar_list_words`, `grammar_ignore_lint(context_hash)`, `grammar_clear_ignored`. (Fallback if 2.5 doesn't expose per-lint hashing publicly: ignore-by-relint with span + kind.)

**Frontend**:
- New `src/stores/grammar-store.ts` (the logs-panel contract — freeze this shape first): per-file diagnostics map mirrored from each linter pass, `grammarTotalCount()`, cleared on project switch / toggle-off.
- `src/lib/grammar/cm6.ts`: `markClass: cm-lint-<kind>` per diagnostic; kind chip via `renderMessage` (stays within @codemirror/lint tooltips); actions = up to 3 replacements + "Add to dictionary" (Spelling) + "Ignore" (all), each followed by `forceLinting`. Dialect from the new `grammar.language` setting; include it in `editorKey` so a dialect change re-lints.
- CSS per kind (theme tokens, all four themes): spelling = red wavy, grammar-class = blue wavy, style-class = dashed.
- Settings (GrammarCard): dialect select (en-US/GB/CA/AU/IN → `grammar.language`, validEnum-registered), "Personal dictionary: N words" management popover, "Reset ignored lints".
- Performance note (documented, not built): whole-doc check per 400ms idle is fine; revisit incremental checking only if >200 KB docs lag.

## 7. Exports: complete all options

**Pandoc (docx + HTML)**: new `src-tauri/src/export_pandoc.rs` — `export_pandoc(project, format) -> path`; registered-root + rootFile validation (the leading-dash guard covers argument injection); `detect::resolve_program("pandoc")` with an actionable install error; `-f latex|typst -t docx|html --standalone` (+ `--embed-resources` for HTML); typst input requires pandoc ≥ 3.1.12 (version-parse, actionable error); output to `<root>/.typeward/build/export.*`; the frontend copies bytes to the save-dialog destination exactly like exportPdf (no new arbitrary-path write IPC). ExportMenu stubs become real; hints note complex-macro conversion limits. Captured stderr capped ~4 KB in error strings.

**PDF + annotations**: add `lopdf`; new `src-tauri/src/export_annotated.rs` — `export_pdf_annotated(project, pdf_path, annotations: Vec<AnnotationInput { file, line, title, body }>) -> { path, annotated, skipped[] }`; `pdf_path` validated under root (promote `synctex.rs::resolve_pdf_under_root` to `pub(crate)`); per annotation: synctex forward (file,line) → (page,x,y), y flipped via MediaBox height, append a `/Text` sticky-note annotation to the page's `/Annots` (UTF-16BE contents); output `.typeward/build/annotated.pdf`; all-skipped with no synctex → actionable error. Frontend: menu item enabled when pdfPath exists + format latex + open threads > 0; flatten thread comments into title/body; extract `offsetToLine` from ReviewPanel into `src/lib/reviews/lines.ts` (shared with items 3 and 10); unopened files read via `readProjectTextFile`; toast "N comments placed" + skipped warning. Typst: item disabled with a "needs SyncTeX" hint. Unit-test the lopdf `/Annots` append on a fixture PDF.

## 8. Logs panel: five tabs

- `compile.rs`: define info severity — LaTeX `Overfull/Underfull \h/vbox` lines → info; Typst `hint:` lines → info (currently dropped). Curated, nothing else. Extend parser tests.
- `LogsDrawer.tsx`: `TABS = All logs (Terminal, no badge) / Errors (XCircle) / Warnings (AlertTriangle) / Info (Info) / Grammar (SpellCheck)` — each tab is icon + name + counter only, **no subheadings** in any body. Bodies: All = raw log pre; Errors/Warnings/Info = a generalized `DiagnosticsList(severity)` of flat IssueCards (the success card and raw-tail fallback stay on Errors); Grammar = rows from grammar-store (all files, `file:line` jump via requestGotoSource), empty state pointing at Settings → Grammar and noting diagnostics appear for opened files. IssueCard gains an info color. Auto-expand on compile error targets the Errors tab.
- `LogsView` (pdf-tab variant): replace the two subtitle SelectorCards with a compact 5-across selector (icon + name + count pill; subtitle prop dropped), same TABS and bodies.

## 9. PDF zoom: fewer presets + fit modes

All in `PdfViewer.tsx` (+ unit tests for an exported pure `computeFitScale`):
- `ZOOM_PRESETS = [50, 75, 100, 125, 150, 200]`; new `zoomMode: number | "fit-width" | "fit-page"` module-level signal (survives remounts = session persistence; seeded from the new `editor.pdfDefaultZoom` setting — single init point). `scale` stays the rendering truth.
- Fit computation: `scrollEl.clientWidth` minus ~48px breathing room over the current page's scale-1 width (fit-page: `clientHeight − ~32px` over height); clamp [0.25, 4]. An effect over (zoomMode, pageSizes, containerSize) sets scale through the existing anchoring; a ResizeObserver on scrollEl (rAF-coalesced) feeds containerSize, active only in fit modes. Selecting a numeric preset exits fit mode.
- Mixed page sizes: fit computes against the current page; scrolling across different-sized pages does NOT re-fit (jitter). Re-fit on mode select, container resize, and doc reload while in a fit mode.
- Dropdown: `Fit width` / `Fit page` entries above the numeric list; the toolbar button always shows `round(scale*100)%`; `aria-selected` compares zoomMode (fixes the current fuzzy match).

## 10. PDF text layer + selection + review/TODO threads anchored in the PDF

Three shippable stages. **Desktop-only** (tablet gated out: memory + swipe-gesture conflicts). Build with the item-11 host seam from the start: props in, callbacks out, no new direct store reads in PdfViewer.

**10a Text layer**: per-page pdf.js `TextLayer` inside the existing virtualized lifecycle — the page box gains a highlight-overlay div + text-layer div; `PageSlot` gains textLayer/textHost/cached `getTextContent()` per load generation; `--scale-factor` set on the page box (v6 requirement); `update({viewport})` on zoom, rebuild on reload, `cancel()` on unrender/cleanup. New minimal `pdf-text-layer.css` (do not import pdf_viewer.css); `::selection` uses `--color-text-selection`. Inverse-search coexistence: dblclick bails when a selection resulted (`!getSelection().isCollapsed`) — dblclick on text selects a word, on whitespace still jumps to source; "Jump to source" also lives on the selection chip.

**10b Create from PDF selection**: `CommentThread` gains `kind?: "comment" | "todo"` (additive; `createThread` optional param; `loadThreads` normalizes) — the seam item 3's TodoPanel thread branch consumes. Refactor: extract `resolveInverse(p, outputPath, page, x, y) -> { relPath, line } | null` into `src/adapters/latex/synctex.ts` (splits lookup from navigation). Selection chip (document `selectionchange`, endpoints inside this viewer's text layer): floating chip with **Comment / TODO / Jump to source** + an inline mini composer. Mapping to source offsets — new pure `src/lib/pdf-annotations/anchor.ts`: synctex inverse gives the line; `matchSelectionToSource` slides a word-window over markup-stripped source lines (synctexLine ± 5; words keep original offsets; score ≥ 0.6 with 1-in-5 mismatch tolerance for hyphenation/ligatures); fallback anchors the whole synctex line. The composer states "anchored to selection" vs "anchored to line N" (honest precision — synctex is line-granular). The thread lands via existing `createThread`/`addThread` (editor decorations come free); panel targeting via `requestReviewPanelIntent(threadId)`.

**10c Render thread highlights in the PDF**: new `src/lib/pdf-annotations/mapper.ts` — per open thread (cap 200): offset → line (reuse `src/lib/reviews/lines.ts`; content cached per relPath, invalidated on fsVersion), synctex forward → page + y (engine-resolved via `effectiveBuild` for the wasm-vs-CLI branch), locate anchorText among text items within y ± 30pt → rects in PDF points; fallback = a full-width line bar at the synctex y (pulse-ribbon geometry minus animation). Memoized by (pdfVersion, threadId, offsets, contentHash); a serial queue (concurrency 2) for synctex subprocess spawns; idle while previewMode ≠ pdf. Overlay divs are `pointer-events: none`; comment = accent-1 25% wash, TODO = warn-tinted (theme tokens). Click routing: the page-box click handler hit-tests the highlight registry (avoids z-order fights with the text layer) → opens the review panel targeted at the thread. Tectonic-without-synctex → chip Comment/TODO disabled with a "needs SyncTeX" tooltip.

## 11. Detached PDF window (editor + PDF in separate OS windows)

- **Creation: frontend** `WebviewWindow("preview", { url: "index.html?window=preview", ... })` — a query param, not a router path (SPA-fallback-proof under the prod asset protocol; boot-theme.js + splash run identically). The main capability adds `core:webview:allow-create-webview-window` + `core:window:allow-set-focus`; new `src-tauri/capabilities/preview.json` scoped to `windows: ["preview"]` with `core:default` + `fs:allow-read-file $DOCUMENT/**` only (no dialog/write/shell). Registered-root gates remain the real guard for custom commands.
- **Boot split**: `src/index.tsx` branches on the query param BEFORE importing App (App.tsx runs autosave/cloud-sync boot side effects at module scope) — dynamic-import either `App` or a new slim `PreviewWindowApp` (theme boot from localStorage + `initCustomThemes()` + PdfViewer + minimal toolbar; no editor stores/watcher/LSP).
- **Bridge** `src/lib/preview-window/bridge.ts` — typed unions over two event channels: down (`state { pdfPath, pdfVersion, compiling, theme, annotations }`, `scroll-target`, `detach-end`), up (`ready`, `recompile`, `inverse`, `open-thread`, `create-thread { kind, page, x, y, selectedText, body }`). Handshake: the preview listens first, then emits `ready`; main replies with full state and rebroadcasts on change (idempotent). Main also re-broadcasts at editor mount if a preview window already exists (HMR/reload recovery).
- **Item 10 in the detached window: read + create both ship via the bridge** — the mapper output (`AnnotationSnapshot` = display-ready rects in PDF points) renders anywhere; creation sends `(kind, page, x, y, selectedText, body)` up; main owns review-store/synctex/files. `PdfViewer` gains an optional `host` prop (onInverse / onRecompile / onOpenThread / onCreateThread / annotations / showExport) — the main window implements it with direct calls, the preview with bridge emits. ExportMenu + AI/console toggles are hidden in the preview window.
- **Layout**: new session-scoped `previewDetached` signal in ui-store (does NOT overwrite `editorLayout` — preserves the split preference); `showPreview() = editorLayout() !== "editor" && !previewDetached()`. Detach button (desktop main window only): focuses the existing window if present, else creates it; a `tauri://destroyed` listener restores the split; the preview's "reattach" button just closes itself. Not persisted across restarts (v1); Mod+Enter inside the preview not wired v1 (the Recompile button exists); zoom is window-local by design.

## Cross-item seams

- The `requestReviewPanel` payload intent (item 3) lands first; items 10 and 11 consume `requestReviewPanelIntent(threadId)`.
- `CommentThread.kind` is added in item 10b; item 3's TodoPanel ships with the `TodoEntry` union populated by scan only until then.
- `src/lib/reviews/lines.ts` (`offsetToLine`) is extracted in items 3/7 and reused by item 10c's mapper.
- `effectiveBuild()` (item 4) is what item 10c's mapper and actions.ts synctex branches use for engine resolution.
- The grammar-store shape (item 6) is frozen before item 8's Grammar tab consumes it.
- Items 5 → 1 → 3 all touch `EditorSidebar.tsx` — implement in that order, never in parallel.

## Sequencing

5 (icon tabs) → 1 (refs gate) → 3 (review targeting + TODO scan) → 2 (outline) → 6 (Harper) → 8 (logs tabs) → 4 (build controls) → 7 (exports) → 9 (zoom) → 10a→b→c (PDF annotations) → 11 (detached window).
