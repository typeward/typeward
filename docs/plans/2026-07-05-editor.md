Fifteen items, numbered to match the original request. Key findings verified during planning (2026-07-05):

- **Detach-span bug root cause found** (item 7): in `text-shell.tsx` the editor-only / preview-only fallbacks render `<div class="flex min-h-0 flex-1">{editorPane()}</div>` — a **row-flex wrapper** whose only child (`CenterPane`/`PreviewPane` root: `glass flex h-full flex-col overflow-hidden rounded-xl`, no width class) gets default `flex: 0 1 auto` and therefore **shrink-to-fit width**, not the pane width. The `previewDetached` signal plumbing itself is correct (bridge → ui-store → `showPreview()`); the Switch collapses as designed. The same latent bug affects the "Editor only" and "PDF only" layouts. Four wrappers (2 in `focusLayout` L395/L398, 2 in the normal layout L470/L473).

All classes are stable; the package's `baseTheme` (5px severity border-left etc.) is overridable with plain CSS, as the existing `.cm-lintRange` overrides already prove. **No custom `hoverTooltip` needed.**
- `design_files/design_samples/harper.png` verified: per-word colored underline + same-hue background wash (red/amber/green/blue families); right-hand "Problems" panel with total-count header, per-category dot+count chips, expandable per-issue cards; bottom status bar `● 13 problems | 123 words 738 chars`.

- No `--color-info` token exists (only ok/warn/err + accents); custom-theme validation in `themes.rs` is pattern-based, not allowlisted, so a new token needs only `tokens.css` per-theme values.

## 2. Real file autosave, default ON

- **Setting**: `EditorSettings.autosaveEnabled: boolean` (default `true`) in `settings-store.ts` (`DEFAULT_EDITOR` + the merge in `validate` covers old settings.json). SettingsScreen: a Switch row "Autosave" above the existing delay row (L907-919); delay hint reworded to "Idle time before changes are saved (crash-recovery snapshot when autosave is off)."
- **Save path**: extract from `actions.ts` a `saveOpenFile(p: Project, file: OpenFile): Promise<void>` = `writeBufferWithConflictGuard` + `notifyLocalSave(p.rootPath, [file.relPath])` + the autoCompile branch currently in `saveActiveFile` (guarded by `p.rootPath === project()?.rootPath` so a stale flush can't compile the wrong project). `saveActiveFile` delegates to it. Add a **per-file in-flight promise chain** (module map keyed by `file.path`) around the guard-read-write sequence so an autosave and a Mod+S of the same file can never interleave the read-compare-write.
- **`src/lib/autosave/index.ts`**: in the debounce callback AND the switch-away flush branch, branch on `editorSettings().autosaveEnabled`: true → `saveOpenFile(...)` with the captured state (a real save; the existing dirty→clean effect then clears the snapshot); false → today's snapshot write. Everything else (per-file last-content map, dirty→clean snapshot clearing, orphan recovery) stays. Save failures: `recordError` + one toast per file per session (mirrors review-store's one-toast pattern) — autosave must not toast-spam on a full disk.
- **Auto-compile interplay (decision: yes, autosave triggers it)**: "Auto-compile on save" means *on save*; autosave is a save. Because autosave itself fires only after `autosaveDelayMs` idle, compile is naturally idle-debounced; `compileActiveProject`'s compiling-guard absorbs bursts. Documented trade-off: a save landing mid-compile does not queue a trailing recompile — the next idle autosave re-triggers.
- Crash-recovery, cloud push (`notifyLocalSave` → 1.5s coalesce), review-offset flush, and the base-hash conflict sidecar all engage because the real `writeBufferWithConflictGuard` path is reused — nothing bypasses it.

## 4. Mod+S = save + compile

- `actions.ts`: `saveAndCompileActiveProject()` = `await saveAllDirtyFiles(); void compileActiveProject();`. Saving first (not relying on compile's internal save) guarantees **Ctrl+S during an active compile still persists** — `compileActiveProject` just returns early on its compiling-guard, and its own `saveAllDirtyFiles` sees nothing dirty on the next run. No double-compile: `saveAllDirtyFiles` never triggers autoCompile (only `saveActiveFile`/`saveOpenFile` do), and the compiling-guard absorbs the autosave-vs-Mod+S race.
- `boot.ts` `core.save`: title "Save and compile", drop the dirty-only `when` → `when: () => activeFile() !== null`, scope stays `editor`, run → `saveAndCompileActiveProject`. With autosave on this is effectively "compile now" — intended (Overleaf parity). Mod+Enter (`latex.compile`/`typst.compile`) unchanged; the `CodeMirror.tsx` `Mod-Enter` defaultKeymap filter is untouched.
- Update the `handleKeydown` unit tests that assert the dirty gate.
