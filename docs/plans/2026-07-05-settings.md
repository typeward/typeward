## 1. Glow + drop-shadow gating (basic themes flat; styled themes user-toggleable glow)

**Mechanism — `data-glow` attribute, exact `data-ambient`/`data-accent-gradient` pattern, derived from theme category + user toggle:**

- `src/stores/ui-store.ts`: `const [glowEffects, setGlowEffects] = createSignal<boolean>(true)` next to `accentGradient` (L19); export both. In the existing `createRoot` effect block (L47-66) add:
  ```ts
  createEffect(() => {
    const styled = THEME_ROSTER[theme()].category === "styled";
    document.documentElement.dataset.glow = styled && glowEffects() ? "on" : "off";
  });
  ```
  Import `theme`, `THEME_ROSTER` from `~/themes/theme-store` — no cycle (theme-store imports only solid-js). This single effect is the derivation point: basic category forces `off` regardless of the setting; custom themes are covered for free because `custom-themes.ts:60` calls `setTheme(active.base)`, so `theme()` always reflects the base.
- Persistence, one token each following `accentGradient` exactly: `src/ipc/index.ts` `UiSettings` (L334-341) gains `glowEffects: boolean`; `src-tauri/src/settings.rs` `UiSettings` (L88-99) gains `#[serde(rename = "glowEffects", default = "default_true")] pub glow_effects: bool` + `glow_effects: true` in the `Default` impl (L380-391); `settings-store.ts` gains one `field<boolean>` entry after the accentGradient one (L291-298), `read: (s) => s.ui.glowEffects ?? true`.
- `SettingsScreen.tsx` Appearance → Accent card, immediately after the Gradient `Row` (L548-553), and like Gradient **outside** the `customThemeActive()` grayed div so it stays live for custom themes:
  ```tsx
  <Show when={THEME_ROSTER[theme()].category === "styled"}>
    <Row label="Glow" hint="Soft accent glow behind primary buttons and card hovers.">
      <Switch checked={glowEffects()} onChange={setGlowEffects} />
    </Row>
  </Show>
  ```
  Hidden (not disabled) on basic themes — matches the "locked renders nothing" house pattern; the row reappears the moment a styled theme is picked.

**CSS — an off-override block, not `:not()` wrapping.** Wrapping the base rules in `:root:not([data-glow="off"])` would change their specificity and leave basic themes with *dead* hover states. Instead append one block to `utilities.css` right after the `data-accent-gradient="off"` block (L304-324), giving the off state a designed fallback:

```css
:root[data-glow="off"] .glow-accent { box-shadow: none; }
:root[data-glow="off"] .card-shell:hover {
  box-shadow: var(--shadow-glass-inset), var(--shadow-glass-drop);
}
:root[data-glow="off"] .card-glow:hover {
  border-color: var(--color-glass-stroke-strong);
  box-shadow: none;
}
:root[data-glow="off"] .avatar-ring,
:root[data-glow="off"] .avatar-ring-2 { box-shadow: 0 0 0 2px var(--color-bg-base); }
```

Specificity story: `(:root + attr + class + :hover)` beats every base rule; `.lift:hover { filter: brightness(1.18) }` is untouched, so `glow-accent` buttons (LibrarySidebar:80, PdfViewer:847, OnboardingScreen:317, ProjectsScreen:548, CommandPalette:195) keep hover feedback. The dashed New-project tiles (ProjectsScreen:509, 540) set their border inline, which already beat `.card-glow:hover`'s `border-color: transparent` — only the box-shadow changes for them, no regression.

**Drop shadows on basic themes:** in `light.css` (L58-66) and `dark.css` (append — it currently inherits Aurora's dark drops, per its own header comment) set `--shadow-glass-drop`, `--shadow-raised`, `--shadow-accent-btn`, and `--shadow-glass-inset` to `0 0 0 rgb(0 0 0 / 0)`. Keep `--shadow-glass-inset-inner` (the sunken-input affordance). Buttons still read: primary is a solid high-contrast accent fill (`#2563eb` on white / `#5aa2f7` on `#1e1e1e`), secondary keeps `glass-soft` + stroke; the Switch/Slider thumbs lose `--shadow-raised` and get a hairline instead (item 2a's `--color-control-thumb-stroke` — this is why item 2 lands **before** the shadow zeroing).

**Docs:** `design/themes.md` — fix the stale 4-theme roster table (6 themes, Basic/Styled categories), and add to the custom-theme section: *a custom theme inherits its base's category — basing on `light`/`dark` means glows and drop shadows are permanently off; basing on a styled theme leaves glow under the user's Appearance toggle. Themes cannot flip this via tokens (token files carry values, not behavior flags).*

Known cosmetic edge: on a styled theme with glow persisted off, the first frames after boot may show glows until settings load — same class of flash as density/ambient today; not worth new machinery.

## 2. Contrast / readability pass (bounded checklist)

### (a) Switch redesign — dedicated control tokens, constant thumb

Decision on the thumb: **flip away from the state-flipping thumb entirely.** The illegibility complaint comes from the thumb changing color between states (`bg-fg-1` → `accent-fg`): on dark/Aurora the checked thumb is dark ink on a colored track while the unchecked thumb is white on an invisible track — reads inverted. Every platform convention (iOS/macOS/Material) keeps the thumb one color and lets the **track** carry the state. So: thumb constant per theme, off-track made clearly visible, checked track stays `.accent-grad` (no deepened-track token needed — off-gray vs accent is unmistakable, and a thumb hairline covers light accents like Aurora's cyan end). This also decouples the switch from `accents.css` `--color-accent-fg` overrides.

New tokens in `tokens.css` `@theme` (so `bg-control-track-off` etc. exist as Tailwind utilities) + per-theme overrides:

| Theme | `--color-control-track-off` | `--color-control-thumb` | `--color-control-thumb-stroke` |
|---|---|---|---|
| Aurora (`:root` default) | `rgb(255 255 255 / 0.14)` | `#e6e8ec` | `rgb(0 0 0 / 0.30)` |
| dark | `rgb(255 255 255 / 0.16)` | `#ffffff` | `rgb(0 0 0 / 0.30)` |
| lamplight | `rgb(237 230 216 / 0.16)` | `#ede6d8` | `rgb(0 0 0 / 0.30)` |
| light | `rgb(0 0 0 / 0.14)` | `#ffffff` | `rgb(0 0 0 / 0.14)` |
| daylight | `rgb(34 33 30 / 0.13)` | `#fdfbf4` | `rgb(34 33 30 / 0.16)` |
| paper | `rgb(15 23 42 / 0.14)` | `#ffffff` | `rgb(15 23 42 / 0.14)` |

(Opacities are calibrated starting points — final values eyeballed per theme; goal: off-track visibly a pill against both bg-base and glass cards, and obviously different from the accent on-track.) The dark hairline on dark themes is what keeps a white thumb defined on light accents (amber `#e8a34d`, cyan `#22d3ee`) once `--shadow-raised` is zeroed on basic themes.

`Switch.tsx` diff sketch (L36-39):

```tsx
<KSwitch.Control class="... rounded-full border border-glass-stroke-strong bg-control-track-off transition data-[checked]:border-transparent data-[checked]:accent-grad data-[disabled]:opacity-45">
  <KSwitch.Thumb class="block h-[14px] w-[14px] translate-x-[2px] rounded-full border border-[var(--color-control-thumb-stroke)] bg-[var(--color-control-thumb)] shadow-[var(--shadow-raised)] transition-transform data-[checked]:translate-x-[16px]" />
```

— i.e. track `border-glass-stroke bg-glass-fill` → `border-glass-stroke-strong bg-control-track-off`; thumb drops `bg-fg-1` and `data-[checked]:bg-[var(--color-accent-fg)]`, gains the token pair; add `data-[disabled]:opacity-45` (today disabled switches look identical to enabled ones — matters for item 3's UX). Optional polish, same tokens: `Slider.tsx:39` thumb (`bg-fg-1` → the same thumb pair) so the two form controls stay coherent. Add the token trio to the `design/themes.md` per-theme token-groups list.

## 3. Zotero-local disable bug + sibling sweep

- **Root fix** — `IntegrationsPanel.tsx:155`: `disabled={!probe()?.reachable}` → `disabled={!settings().enabled && !probe()?.reachable}`. An enabled provider is always switchable off; only the *enable* direction waits for reachability (also correctly disabled while the probe is pending). With item 2a's `data-[disabled]:opacity-45` the gate finally becomes visible.
- **Sibling sweep (done — verified clean):** the reachability-gated Switch exists exactly once. AI (`:976`) and Grammar (`:1314`) switches are unguarded; ZoteroWeb/Mendeley/Dropbox/WebDAV/GitHub rows use Connect/Disconnect buttons whose `disabled={busy()}` guards are correct. No other changes.
- **Stale `library.bib`** — the "still enabled" half. In `references/init.ts`, after the register/unregister effect settles (L75-101), trigger a rewrite when the provider *plan* changes while a project is open — skipping the first run so boot doesn't fire cold network exports:
  ```ts
  let first = true;
  // at the end of the createEffect body:
  if (first) { first = false; return; }
  const proj = untrack(project);
  if (proj) void refreshLibraryBib(proj).catch((e) => recordError("references-refresh", "post-toggle refresh failed", e));
  ```
  Imports: `project` from `~/stores/editor-store` (leaf — solid-js + adapter types only, no cycle), `refreshLibraryBib` from the aggregator. With zero providers and no local additions the aggregator writes the header-only file (`bibtex.ts` `buildHeader` + empty body), so completions stop resolving Zotero keys — functionally equivalent to deletion without a new IPC (deliberately not added; write-empty is one line and keeps the IPC surface fixed). Accepted residual gap: toggling while *no* project is open leaves the old file until the next open + refresh/DOI action — documented, no machinery.
- Test: extend `aggregator.test.ts` with "writes header-only when no providers are registered and local additions are empty".

## 4. GitHub settings card — verdict: KEEP, no change

What VcsCard (`IntegrationsPanel.tsx:753-763`) actually provides: **AuthorIdentityRow** is the only UI for commit author name/email (git refuses unsigned commits; the system-gitconfig fallback doesn't exist on clean machines — tablets especially); **GithubAccountRow** is the only standalone device-flow sign-in (needed to push/pull a repo that *wasn't* cloned through CloneDialog), the only Disconnect (keyring token revocation from the UI), and the only status surface ("Connected as X" + `credential_exists`). What breaks without it: cloning survives (CloneDialog has its own inline GitHub sign-in and self-contained Overleaf auth, verified at `CloneDialog.tsx:79/203-213`), but disconnect, status, pre-push auth, and author identity all vanish. Slimming was considered and rejected: the card is already two compact rows with distinct concerns (identity vs. auth) — merging them saves ~40px and loses scannability. One honest wart to record: `github/api.ts` `listRepos`/`createRepo` have **zero consumers** (re-exported at `github/index.ts:8-9` only) — leave them as the seed of a future "publish to GitHub" flow, or delete in a separate dead-code sweep; they are not a reason to touch the card.
